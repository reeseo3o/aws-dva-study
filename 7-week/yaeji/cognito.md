# Amazon Cognito 핵심 요약

Amazon Cognito는 웹 및 모바일 애플리케이션에 빠르고 쉽게 사용자 가입, 로그인 및 액세스 제어 기능을 추가할 수 있도록 지원하는 서비스입니다. Cognito는 크게 두 가지 주요 기능으로 구성됩니다: **사용자 풀**과 **자격 증명 풀**.

## 1. Amazon Cognito란?

*   **목표**: 웹 및 모바일 애플리케이션 사용자가 AWS 리소스와 안전하게 상호작용할 수 있도록 자격 증명을 부여합니다.
*   **대상**: 주로 AWS 계정 외부에 있는 애플리케이션 사용자 (수백만 명 규모 가능).
*   **주요 서비스**:
    *   **Cognito 사용자 풀 (User Pools)**: 앱 사용자를 위한 로그인 기능 및 사용자 관리 제공.
    *   **Cognito 자격 증명 풀 (Identity Pools / Federated Identities)**: 앱 사용자가 AWS 리소스에 직접 액세스할 수 있도록 임시 AWS 자격 증명 제공.

## 2. Cognito 사용자 풀 (User Pools)

Cognito 사용자 풀은 애플리케이션 사용자를 위한 안전한 사용자 디렉터리입니다. 사용자의 가입 및 로그인 기능을 제공하며, API Gateway 및 Application Load Balancer (ALB)와 쉽게 통합됩니다.

### 주요 기능 및 설정

*   **인증 공급자**:
    *   **Cognito 사용자 풀 자체**: 이메일, 전화번호, 사용자 이름 및 비밀번호를 사용한 로그인.
    *   **페더레이션 자격 증명 공급자 (Federated Identity Providers)**: Google, Facebook, Amazon, Apple 등 소셜 ID 공급자를 통한 로그인. (SAML 또는 OpenID Connect(OIDC)를 통한 기업 ID 공급자 연동도 지원)
*   **로그인 옵션**: 사용자가 로그인할 때 사용할 식별자 (예: 사용자 이름, 이메일, 전화번호).
*   **보안 요건**:
    *   **비밀번호 정책**: 최소 길이, 문자 조합 등 비밀번호 복잡도 설정.
    *   **다중 인증 (MFA)**: TOTP (시간 기반 일회용 암호) 앱 또는 SMS 문자 메시지를 통한 추가 인증 계층.
*   **계정 복구**: '비밀번호 찾기' 기능 제공 (이메일 또는 SMS).
*   **사용자 속성**:
    *   **표준 속성**: 이메일, 전화번호, 주소, 생일 등 미리 정의된 속성.
    *   **사용자 지정 속성 (Custom Attributes)**: 애플리케이션별 필요한 추가 사용자 정보 저장.
*   **메시지 전송**:
    *   **Amazon SES (Simple Email Service)**: 대량 이메일 발송 및 고급 설정 가능.
    *   **Cognito 기본 이메일/SMS 기능**: 개발 및 테스트 목적 (일일 발송량 제한 있음).
*   **호스팅 UI (Hosted UI)**:
    *   Cognito가 제공하는 가입, 로그인, 비밀번호 재설정 등을 위한 웹 UI.
    *   애플리케이션에 UI를 직접 구축할 필요 없이 빠르게 인증 흐름 구현 가능.
    *   로고 및 CSS를 사용하여 UI 커스터마이징 지원.
    *   **Cognito 도메인 또는 사용자 지정 도메인**을 통해 접근. (사용자 지정 도메인 사용 시 `us-east-1` 리전에 ACM 인증서 필요)
*   **앱 클라이언트 (App Clients)**:
    *   사용자 풀에 등록된 애플리케이션. 각 앱 클라이언트는 고유한 ID를 가짐.
    *   퍼블릭 클라이언트(클라이언트 암호 없음) 또는 프라이빗 클라이언트(클라이언트 암호 사용) 설정 가능.
    *   인증 성공 후 리디렉션될 콜백 URL 설정.
*   **Lambda 트리거 (Lambda Triggers)**:
    *   사용자 풀의 다양한 라이프사이클 이벤트 (예: 가입 전/후, 인증 전/후, 메시지 발송 전 등) 발생 시 Lambda 함수를 호출하여 사용자 지정 로직 실행.
    *   이를 통해 사용자 검증, 속성 사용자 지정, 환영 메시지 발송, 분석 이벤트 로깅 등 다양한 워크플로 자동화 가능.
        *   **가입 트리거 예시**:
            *   **사전 가입 (Pre Sign-up)**: 가입 시 사용자 검증, 속성 사용자 지정.
            *   **사후 확인 (Post Confirmation)**: 사용자 지정 환영 메시지 전송, 분석 이벤트 로깅.
            *   **사용자 마이그레이션 (User Migration)**: 다른 디렉터리에서 사용자 마이그레이션.
        *   **인증 트리거 예시**:
            *   **사전 인증 (Pre Authentication)**: 로그인 요청 승인/거절.
            *   **사후 인증 (Post Authentication)**: 로그인 성공 후 사용자 지정 분석 로깅.
            *   **사전 토큰 생성 (Pre Token Generation)**: ID 토큰에 클레임 추가/수정/억제.
*   **조정 인증 (Adaptive Authentication)**:
    *   로그인 시도에 대한 위험 점수(낮음, 중간, 높음)를 평가하여 의심스러운 로그인 시도에 대해 MFA를 요구하거나 차단.
    *   사용자의 평소 로그인 패턴 (장치, 위치, IP 주소 등)을 학습하여 위험도 판단.
    *   계정 탈취 방지 및 보안 강화.
    *   로그인 시도, 위험 점수, 실패 시도 등은 CloudWatch Logs에 기록.
*   **JSON 웹 토큰 (JWT)**:
    *   인증 성공 시 Cognito는 ID 토큰, 액세스 토큰, 리프레시 토큰을 발급.
    *   토큰은 Base64로 인코딩되며 헤더, 페이로드, 서명으로 구성.
    *   **페이로드**: 사용자 정보 (sub UUID, 사용자 이름, 그룹, 만료 시간 등) 포함. 서명 검증 후 신뢰 가능.
    *   **sub UUID**: Cognito 사용자 풀 데이터베이스의 고유 사용자 ID. 이를 통해 추가 사용자 정보 조회 가능.

## 3. Cognito 자격 증명 풀 (Identity Pools / Federated Identities)

Cognito 자격 증명 풀은 애플리케이션 사용자가 AWS 서비스(예: S3, DynamoDB)에 직접 액세스할 수 있도록 임시 AWS 자격 증명을 제공합니다. 이를 **연합 인증(Federated Identities)**이라고도 합니다.

### 주요 기능 및 설정

*   **핵심 역할**: AWS 리소스에 대한 **권한 부여 (Authorization)**.
*   **임시 AWS 자격 증명**: STS (Security Token Service)를 통해 임시 보안 자격 증명(액세스 키 ID, 보안 액세스 키, 세션 토큰)을 사용자에게 제공.
*   **인증되지 않은 액세스 (Guest Access)**: 로그인하지 않은 사용자(게스트)에게도 제한된 AWS 리소스 접근 권한 부여 가능.
*   **자격 증명 공급자 (Identity Providers)**:
    *   **Amazon Cognito 사용자 풀**: 사용자 풀에 로그인한 사용자를 인증.
    *   **공용 공급자 (Public Providers)**: Amazon, Facebook, Google, Apple 등 소셜 로그인.
    *   **OpenID Connect (OIDC) 공급자**.
    *   **SAML 자격 증명 공급자**.
    *   **개발자 인증 자격 증명 (Developer Authenticated Identities)**: 자체 로그인 시스템을 통해 인증된 사용자에게 자격 증명 부여.
*   **IAM 역할 및 정책**:
    *   인증된 사용자와 인증되지 않은 사용자 각각에 대해 다른 IAM 역할을 할당 가능.
    *   사용자 ID 또는 토큰의 클레임에 따라 동적으로 IAM 역할을 선택하는 규칙 정의 가능.
    *   IAM 정책 변수 (`${cognito-identity.amazonaws.com:sub}` 등)를 사용하여 사용자별로 세분화된 액세스 제어 (예: S3 버킷의 특정 사용자 폴더만 접근 허용, DynamoDB의 특정 사용자 데이터만 접근 허용).
*   **워크플로**:
    1.  사용자가 선택한 자격 증명 공급자(예: Cognito 사용자 풀, Facebook)를 통해 로그인하고 토큰(ID 토큰 또는 액세스 토큰)을 받습니다.
    2.  애플리케이션은 이 토큰을 Cognito 자격 증명 풀에 전달합니다.
    3.  Cognito 자격 증명 풀은 해당 자격 증명 공급자를 통해 토큰을 검증합니다.
    4.  검증 성공 시, Cognito 자격 증명 풀은 STS와 통신하여 임시 AWS 자격 증명을 획득합니다.
    5.  이 자격 증명은 애플리케이션으로 반환됩니다.
    6.  애플리케이션은 이 자격 증명을 사용하여 AWS SDK를 통해 AWS 서비스에 직접 API 호출을 수행합니다.

## 4. Cognito 사용자 풀 vs. 자격 증명 풀

| 구분             | Cognito 사용자 풀 (User Pools)                                 | Cognito 자격 증명 풀 (Identity Pools)                                  |
| :--------------- | :----------------------------------------------------------- | :------------------------------------------------------------------- |
| **주요 목적**    | **인증 (Authentication)** - 사용자가 누구인지 확인                   | **권한 부여 (Authorization)** - 사용자가 무엇을 할 수 있는지 제어          |
| **기능**         | 사용자 디렉터리, 가입/로그인, 토큰 발급, 페더레이션 로그인, MFA | AWS 서비스 접근을 위한 임시 자격 증명 발급, IAM 역할 매핑            |
| **결과물**       | JWT (ID 토큰, 액세스 토큰, 리프레시 토큰)                          | 임시 AWS 자격 증명 (액세스 키, 비밀 키, 세션 토큰)                     |
| **단독 사용**    | 가능 (사용자 인증 및 관리만 필요한 경우)                           | 가능 (자체 인증 시스템 또는 외부 IDP 사용 시)                          |
| **AWS 리소스 접근** | 직접 제공 안 함 (ID 토큰을 API Gateway Authorizer 등으로 활용)   | 직접 제공 (임시 자격 증명을 통해 AWS 서비스 API 호출)                  |

### 함께 사용하는 시나리오

가장 일반적인 시나리오는 사용자 풀과 자격 증명 풀을 함께 사용하는 것입니다.

1.  **사용자 인증 (사용자 풀)**: 사용자는 Cognito 사용자 풀 (또는 사용자 풀에 연결된 페더레이션 ID 공급자)을 통해 로그인하고 ID 토큰을 받습니다.
2.  **권한 부여 (자격 증명 풀)**: 이 ID 토큰을 Cognito 자격 증명 풀에 전달하여 임시 AWS 자격 증명을 받습니다.
3.  **AWS 리소스 접근**: 획득한 임시 자격 증명을 사용하여 AWS S3, DynamoDB 등의 서비스에 안전하게 접근합니다.

이 방식을 통해 사용자 인증과 AWS 리소스 접근 권한 관리를 분리하여 강력하고 유연한 보안 모델을 구축할 수 있습니다.

## 5. Cognito와 다른 AWS 서비스 연동

### 5.1 API Gateway와 통합

*   Cognito 사용자 풀을 API Gateway의 Authorizer로 사용하여 API에 대한 접근 제어.
*   클라이언트가 API 호출 시 ID 토큰을 Authorization 헤더에 담아 전송하면, API Gateway가 토큰을 검증하고 인증된 사용자만 API를 호출하도록 허용.

### 5.2 Application Load Balancer (ALB)와 통합

ALB는 Cognito 사용자 풀 또는 OIDC 호환 자격 증명 공급자를 사용하여 사용자를 인증할 수 있습니다. 이를 통해 애플리케이션 코드에서 인증 로직을 분리할 수 있습니다.

*   **ALB + Cognito 사용자 풀**:
    1.  사용자가 ALB를 통해 애플리케이션에 접근 시도.
    2.  ALB는 사용자를 Cognito 호스팅 UI로 리디렉션하여 로그인 요청.
    3.  로그인 성공 시 Cognito는 ID 토큰을 반환.
    4.  ALB는 이 토큰을 검증하고, 사용자 정보를 담아 백엔드 애플리케이션(예: ECS, EC2)으로 요청 전달.
*   **ALB + OIDC**:
    1.  유사한 흐름이지만, Cognito 대신 외부 OIDC 자격 증명 공급자의 인증 엔드포인트, 토큰 엔드포인트, 사용자 정보 엔드포인트 등을 ALB에 직접 설정.
*   **필수 조건**: 보안을 위해 HTTPS 리스너 설정 필요.
*   **인증 실패 시 처리**: 인증 요청, 모든 요청 거부, 모든 요청 허용 중 선택 가능 (예: 로그인 페이지는 인증 없이 접근 허용).
