*   **DynamoDB 기본**
    *   NoSQL 데이터베이스로서 관계형 데이터베이스(RDBMS)와의 차이점, 수평적 확장성 등을 설명합니다.
    *   테이블, 항목(행), 속성(열)으로 구성되며, 각 항목은 최대 400KB의 크기 제한을 가집니다.
    *   다양한 데이터 타입(스칼라, 문서, 집합)을 지원합니다.
    *   기본 키는 파티션 키(단독) 또는 파티션 키와 정렬 키(조합)로 구성되며, 데이터 분산에 중요한 역할을 합니다.

*   **읽기/쓰기 용량 모드**
    *   **프로비저닝 모드** 사전에 읽기 용량 유닛(RCU)과 쓰기 용량 유닛(WCU)을 설정하고 비용을 지불합니다. 오토 스케일링 옵션이 있으며, 용량 초과 시 "프로비저닝 처리량 초과 예외"가 발생할 수 있습니다.
        *   WCU: 1KB 크기 항목에 대해 초당 1회 쓰기. 항목 크기가 더 크면 올림하여 계산.
        *   RCU: 4KB 크기 항목에 대해 초당 강력한 일관된 읽기 1회 또는 최종적 일관된 읽기 2회. 항목 크기가 더 크면 올림하여 계산. 최종적 일관된 읽기가 기본이며, 강력한 일관된 읽기는 더 많은 RCU를 소모하고 지연 시간이 높을 수 있습니다.
    *   **온디맨드 모드** 워크로드에 따라 자동으로 스케일링되며, 사용한 만큼 비용을 지불합니다. 프로비저닝 모드보다 비쌉니다.

*   **API 및 작업**
    *   데이터 쓰기: `PutItem`(새 항목 생성 또는 전체 교체), `UpdateItem`(기존 항목 속성 편집 또는 새 항목 추가), 조건부 쓰기.
    *   데이터 읽기: `GetItem`(기본 키 기반 단일 항목 읽기), `Query`(파티션 키 및 선택적 정렬 키 조건으로 항목 검색), `Scan`(테이블 전체 읽기, 비효율적일 수 있음).
    *   일괄 작업: `BatchWriteItem`(최대 25개 Put/Delete), `BatchGetItem`(최대 100개 항목).
    *   데이터 삭제: `DeleteItem`(개별 항목 삭제), `DeleteTable`(테이블 전체 삭제).
    *   **PartiQL** SQL과 유사한 쿼리 언어를 사용하여 DynamoDB 데이터 조작 가능.

*   **조건부 쓰기 및 낙관적 잠금** 특정 조건이 충족될 때만 쓰기 작업을 수행하여 데이터 일관성을 유지하고 동시성 문제를 해결합니다. 버전 번호 등을 활용합니다.

*   **인덱스**
    *   **로컬 보조 인덱스(LSI)** 테이블 생성 시 정의해야 하며, 기본 테이블과 동일한 파티션 키를 사용하고 다른 정렬 키를 제공하여 쿼리 유연성을 높입니다. 테이블당 최대 5개.
    *   **글로벌 보조 인덱스(GSI)** 테이블 생성 후에도 추가 가능하며, 다른 파티션 키 및 정렬 키를 가질 수 있어 다양한 쿼리 패턴을 지원합니다. 자체적인 RCU/WCU 프로비저닝이 필요합니다. GSI 쓰기 스로틀 시 메인 테이블도 스로틀될 수 있습니다.

*   **DynamoDB Accelerator (DAX)** 완전 관리형 인 메모리 캐시 서비스로, 읽기 집약적인 워크로드의 성능을 향상시키고 RCU 비용을 절감합니다. 특히 핫 키 문제 해결에 유용합니다.

*   **DynamoDB Streams** 테이블 항목의 변경 사항(생성, 업데이트, 삭제)을 시간 순서대로 캡처하여 스트림으로 제공합니다. AWS Lambda, Kinesis Data Streams 등과 통합하여 실시간 데이터 처리, 분석, 트리거 기반 작업 등을 수행할 수 있습니다. 데이터 보존 기간은 최대 24시간입니다.

*   **Time To Live (TTL)** 특정 타임스탬프 속성을 기준으로 만료된 항목을 자동으로 삭제하는 기능입니다. WCU를 소모하지 않으며, 세션 데이터 관리나 규제 준수 등에 유용합니다.

*   **CLI 옵션**
    *   `--projection-expression`: 특정 속성만 선택적으로 가져옵니다.
    *   `--filter-expression`: 반환되는 항목을 클라이언트 측에서 필터링합니다.
    *   `--page-size`: 한 번의 API 호출로 가져올 데이터 양을 조절하여 시간 초과를 방지합니다.
    *   `--max-items` 및 `--starting-token`: 페이지네이션을 통해 결과를 나누어 받습니다.

*   **트랜잭션** 여러 항목이나 여러 테이블에 걸쳐 모든 작업이 성공하거나 모두 실패하도록 보장(ACID)합니다. `TransactGetItems`와 `TransactWriteItems` API를 사용하며, 일반 작업보다 두 배의 용량 단위를 소비합니다.

*   **기타 주요 기능 및 고려 사항**
    *   **세션 상태 저장**: ElastiCache와 함께 웹 애플리케이션의 세션 상태 저장소로 활용될 수 있습니다.
    *   **쓰기 샤딩**: 핫 파티션 문제를 해결하기 위해 파티션 키 값에 접미사/접두사를 추가하여 쓰기를 분산시키는 전략입니다.
    *   **S3와의 통합**: 큰 객체는 S3에 저장하고 메타데이터나 포인터를 DynamoDB에 저장하거나, S3 객체 메타데이터의 인덱스로 DynamoDB를 활용합니다.
    *   **테이블 정리**: Scan 후 개별 삭제보다 `DeleteTable` 후 재생성하는 것이 효율적입니다.
    *   **테이블 복제**: AWS Data Pipeline, 백업/복구, 또는 사용자 지정 코드를 통해 다른 리전이나 계정으로 복제 가능합니다.
    *   **보안**: VPC 엔드포인트, IAM을 통한 액세스 제어, KMS를 이용한 미사용 데이터 암호화, SSL/TLS를 이용한 전송 중 데이터 암호화를 지원합니다.
    *   **글로벌 테이블**: 다중 리전, 다중 활성화 복제를 지원하여 전 세계 사용자에게 낮은 지연 시간을 제공합니다.
    *   **DynamoDB Local**: 로컬 개발 및 테스트를 위한 시뮬레이션 환경입니다.
    *   **AWS Database Migration Service (DMS)**: 다른 데이터베이스에서 DynamoDB로 또는 그 반대로 데이터를 마이그레이션합니다.
    *   **파인 그레인 액세스 제어**: Amazon Cognito와 같은 신분 제공자를 통해 IAM 역할과 조건을 사용하여 사용자가 자신의 데이터에만 접근하도록 행 및 속성 수준에서 세밀하게 권한을 제어합니다.
