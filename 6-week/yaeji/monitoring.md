## AWS 모니터링, 트러블슈팅, 감사 서비스 요약 (CloudWatch, X-Ray, CloudTrail)

애플리케이션을 배포하고 운영할 때, 단순히 잘 구축하는 것만큼 중요한 것이 바로 시스템의 상태를 지속적으로 관찰하고 문제가 발생했을 때 신속하게 해결하며, 모든 활동 기록을 관리하는 것입니다. AWS는 이를 위해 강력한 모니터링, 트러블슈팅, 감사 도구를 제공합니다.

### 1. 왜 모니터링이 중요한가?

*   **사용자 경험:** 지연 시간 증가나 서비스 중단은 사용자 만족도를 떨어뜨립니다. 문제가 발생하기 전에 예측하거나, 발생 즉시 사용자가 알기 전에 해결해야 합니다.
*   **사전 문제 해결:** 장애가 발생하기 전에 잠재적 위험을 감지하고 예방 조치를 취할 수 있습니다.
*   **성능 및 비용 최적화:** 시스템의 성능 추이를 분석하고 리소스 사용 패턴을 파악하여 불필요한 비용을 줄이고 효율적인 운영 방안을 모색할 수 있습니다.
*   **지속적인 개선:** 모니터링 데이터를 기반으로 시스템의 약점을 파악하고 개선하여 더 안정적이고 성능 좋은 서비스를 제공할 수 있습니다.

### 2. AWS 핵심 모니터링/감사 서비스

#### 2.1. Amazon CloudWatch: 포괄적인 모니터링 허브

CloudWatch는 AWS 리소스와 애플리케이션에 대한 **중앙 집중식 모니터링 서비스**입니다. 다양한 데이터를 수집, 시각화하고 알림을 설정할 수 있습니다.

*   **주요 기능:**
    *   **Metrics (지표):**
        *   AWS 서비스(EC2 CPU 사용률, ELB 요청 수 등)의 성능 데이터를 수집합니다.
        *   **사용자 지정 지표(Custom Metrics):** 애플리케이션 레벨의 데이터(메모리 사용량, 로그인 사용자 수 등)를 `PutMetricData` API를 통해 직접 CloudWatch로 전송할 수 있습니다.
        *   **모니터링 간격:** 기본(5분), 세부(1분, 유료) 모니터링 옵션이 있습니다. 세부 모니터링은 더 빠른 대응과 오토 스케일링 최적화에 유리합니다.
        *   **대시보드:** 여러 지표를 한눈에 볼 수 있는 맞춤형 시각화 대시보드를 생성합니다.
    *   **Logs (로그):**
        *   애플리케이션 및 시스템 로그를 수집, 저장, 분석합니다. (SDK, Agent, Beanstalk, ECS, Lambda, VPC Flow Logs, API Gateway, CloudTrail 등 다양한 소스 지원)
        *   **로그 그룹/스트림:** 로그를 논리적으로 구성하고 관리합니다. (예: 애플리케이션별 그룹, 인스턴스별 스트림)
        *   **보존 정책:** 로그 보관 기간을 설정합니다. (1일 ~ 10년 또는 영구)
        *   **Logs Insights:** 강력한 쿼리 언어를 사용하여 대규모 로그 데이터를 신속하게 검색하고 분석합니다.
        *   **로그 내보내기/스트리밍:** S3(배치), Kinesis Data Streams/Firehose, Lambda, OpenSearch 등으로 로그를 전송하여 추가 분석이나 장기 보관에 활용합니다. (실시간 처리는 구독 필터 사용)
        *   **Live Tail:** 실시간으로 들어오는 로그를 확인하며 디버깅할 수 있습니다. (무료 사용량 제한 있음)
    *   **Alarms (경보):**
        *   지표 값이 특정 임계값을 넘거나 미달할 때 알림을 받거나 조치를 자동으로 수행합니다.
        *   **상태:** `OK`, `ALARM`, `INSUFFICIENT_DATA`.
        *   **작업:** EC2 인스턴스 작업(중지, 종료, 재부팅, 복구), Auto Scaling 작업(스케일 인/아웃), SNS 알림 발송.
        *   **Composite Alarms (복합 경보):** 여러 경보의 상태를 조합(AND/OR)하여 더 복잡한 조건으로 알림을 발생시켜 불필요한 노이즈를 줄입니다.
    *   **Events (이벤트, 현 EventBridge):**
        *   AWS 환경 내의 이벤트(EC2 인스턴스 상태 변경, S3 객체 생성, API 호출 등)에 반응하여 자동화된 작업을 트리거합니다.
        *   **스케줄링:** Cron과 유사하게 주기적인 작업(Lambda 함수 호출 등)을 예약합니다.
        *   **이벤트 소스:** AWS 서비스, 사용자 지정 애플리케이션, SaaS 파트너(파트너 이벤트 버스 사용).
        *   **대상:** Lambda, SQS, SNS, Step Functions, CodePipeline 등 다양한 서비스로 이벤트를 라우팅합니다.
        *   **스키마 레지스트리:** 이벤트 구조(스키마)를 자동으로 감지하고 관리하여 코드 생성 등에 활용합니다.
    *   **Synthetics Canary:**
        *   사용자 경험을 시뮬레이션하는 스크립트(Node.js, Python)를 주기적으로 실행하여 웹사이트, API 엔드포인트의 가용성, 성능, 기능(로그인, 장바구니 등)을 테스트합니다.
        *   스크린샷, 로드 시간 데이터 등을 저장하며, 문제 발생 시 경보를 트리거할 수 있습니다.

*   **데이터 수집 방식 (EC2/온프레미스):**
    *   **CloudWatch Agent:** 로그 및 시스템 수준 지표(RAM, Disk IO, 프로세스 등)를 수집하기 위해 인스턴스에 설치해야 하는 소프트웨어입니다. (구버전: Logs Agent, 최신: Unified Agent)
    *   Unified Agent는 로그와 상세 지표를 모두 수집하며 중앙 집중식 구성이 가능합니다.

*   **도식화 (간단 흐름):**
    ```
    [EC2/온프레미스 서버] ---> [CloudWatch Agent] ---> [CloudWatch]
                                                     |--> Metrics (지표)
                                                     |--> Logs (로그) --> Log Insights, Alarms, S3 Export 등
    ```

#### 2.2. AWS X-Ray: 분산 시스템 추적 및 성능 분석

X-Ray는 마이크로서비스와 같은 **분산 애플리케이션의 요청 흐름을 추적하고 성능 병목 구간 및 오류를 시각적으로 분석**하는 서비스입니다.

*   **주요 기능:**
    *   **엔드투엔드 추적 (Tracing):** 사용자 요청이 시스템 내 여러 컴포넌트를 거치는 전체 경로를 추적합니다.
    *   **서비스 맵 (Service Map):** 애플리케이션 구성 요소 간의 연결 관계, 각 노드의 상태(성공, 오류, 지연 등)를 시각적으로 보여줍니다. 이를 통해 문제 발생 지점을 빠르게 파악할 수 있습니다.
    *   **성능 병목 식별:** 각 서비스 또는 외부 호출(DB, API 등)에서 소요되는 시간을 분석하여 지연의 원인을 찾습니다.
    *   **오류 및 예외 분석:** 요청 처리 중 발생한 오류와 예외 정보를 수집하고 분석합니다.
    *   **어노테이션(Annotations) & 메타데이터(Metadata):**
        *   **어노테이션:** 추적 데이터에 추가하는 Key-Value 정보. **인덱싱**되어 추적 검색 및 필터링에 사용됩니다. (예: `userID`, `orderID`)
        *   **메타데이터:** 추가적인 Key-Value 정보. 인덱싱되지 않아 검색에는 사용되지 않지만, 특정 추적 내에서 부가 정보를 확인하는 데 유용합니다.
    *   **샘플링 (Sampling):** 모든 요청을 추적하면 비용이 증가하므로, 정의된 규칙(예: 초당 첫 요청 + 추가 요청의 5%)에 따라 일부 요청만 샘플링하여 추적합니다. 비용과 데이터 상세도 간의 균형을 맞출 수 있습니다.

*   **작동 방식:**
    1.  **코드 계측 (Instrumentation):** 애플리케이션 코드에 **X-Ray SDK**를 통합하여 추적 데이터를 생성하도록 수정합니다. (Java, Python, Go, Node.js, .NET 지원)
    2.  **X-Ray 데몬 실행:** EC2, ECS, 온프레미스 환경에서는 X-Ray 데몬(에이전트)을 실행하여 SDK로부터 UDP를 통해 추적 데이터를 수집하고 X-Ray 서비스로 전송합니다. Lambda, Beanstalk 등 일부 관리형 서비스는 데몬 실행을 자동화하거나 옵션으로 제공합니다.
    3.  **IAM 권한:** 애플리케이션 또는 데몬이 X-Ray 서비스에 데이터를 전송할 수 있는 적절한 IAM 권한이 필요합니다.

*   **도식화 (간단 흐름):**
    ```
    [사용자 요청] --> [애플리케이션 (X-Ray SDK 계측)] --> [X-Ray 데몬] --> [AWS X-Ray 서비스]
                                                                         |--> Service Map 생성
                                                                         |--> Trace 데이터 분석/저장
    ```

#### 2.3. AWS CloudTrail: API 활동 감사 및 거버넌스

CloudTrail은 AWS 계정 내에서 수행된 **모든 API 호출 기록을 로깅하여 감사, 보안 분석, 규정 준수 및 운영 문제 해결**에 사용하는 서비스입니다. "누가, 언제, 무엇을 했는가?"에 대한 답을 제공합니다.

*   **주요 기능:**
    *   **API 활동 로깅:** 콘솔, SDK, CLI, AWS 서비스를 통해 이루어진 모든 API 호출을 기록합니다. (기본 활성화)
    *   **이벤트 유형:**
        *   **관리 이벤트 (Management Events):** 리소스 생성, 수정, 삭제 등 계정 내 리소스에 대한 작업 기록 (기본 로깅됨). 읽기/쓰기 구분 가능.
        *   **데이터 이벤트 (Data Events):** S3 객체 수준 활동(GetObject, PutObject)이나 Lambda 함수 호출과 같이 리소스 자체에 대한 작업 기록. 대용량 이벤트이므로 **기본적으로 로깅되지 않음**. 필요시 활성화.
        *   **인사이트 이벤트 (Insights Events):** CloudTrail 로그를 분석하여 비정상적인 API 활동 패턴(예: 특정 API 호출 급증)을 자동으로 감지 (유료 기능).
    *   **로그 저장 및 분석:**
        *   CloudTrail 콘솔에서 최근 90일간의 이벤트 확인 가능.
        *   장기 보관 및 분석을 위해 S3 버킷으로 로그 전송 설정 가능 (Athena로 쿼리).
        *   CloudWatch Logs로 전송하여 Logs Insights로 분석하거나 Metric Filter/Alarm과 연동 가능.
    *   **다중 리전 추적:** 여러 리전의 이벤트를 단일 S3 버킷 또는 CloudWatch Logs 로그 그룹으로 통합 관리 가능.

*   **활용 사례:**
    *   **보안 감사:** 특정 리소스 변경 이력 추적, 사용자 활동 모니터링, 무단 접근 시도 감지.
    *   **운영 문제 해결:** 예상치 못한 리소스 변경의 원인 파악 (예: "누가 이 EC2 인스턴스를 종료했나?").
    *   **규정 준수:** 특정 규제 요건(예: HIPAA, PCI DSS)을 위한 활동 기록 증빙.
    *   **자동화 연동:** EventBridge와 연동하여 특정 API 호출(예: 루트 사용자 로그인, 보안 그룹 변경) 발생 시 실시간 알림 또는 자동 대응 조치 수행.

*   **도식화 (간단 흐름):**
    ```
    [사용자/서비스] --(API Call)--> [AWS 서비스]
                                      |
                                      v
                                  [CloudTrail] ----> [Event History (90일)]
                                      |------------> [S3 버킷 (장기 보관)] --> [Athena 쿼리]
                                      |------------> [CloudWatch Logs] -----> [Logs Insights, Alarms]
                                      |------------> [EventBridge] ---------> [SNS, Lambda 등 자동화]
    ```

### 3. 서비스 간 비교 요약

| 구분        | CloudWatch                                     | X-Ray                                             | CloudTrail                                       |
| :---------- | :--------------------------------------------- | :------------------------------------------------ | :----------------------------------------------- |
| **주요 목적** | 운영 상태 모니터링 (리소스, 애플리케이션)          | 분산 시스템 성능 분석 및 디버깅                       | API 활동 감사, 보안, 규정 준수                     |
| **핵심 데이터** | 지표(Metrics), 로그(Logs), 이벤트(Events)       | 추적(Traces), 세그먼트(Segments), 서비스 맵(Service Map) | API 호출 기록 (이벤트)                            |
| **주요 기능** | 대시보드, 경보, 로그 분석, 자동화(EventBridge) | 요청 추적, 병목 식별, 오류 분석, 시각화               | 활동 기록, 변경 추적, 보안 분석, 규정 준수 증빙        |
| **관점**      | 시스템/리소스의 전반적인 상태 및 성능             | 개별 요청의 흐름 및 처리 과정                        | 계정 내에서 발생한 모든 관리/데이터 작업             |
| **주요 질문** | "CPU 사용률은?", "로그에 에러가 있나?", "상태 변경 시 알림" | "요청 처리가 왜 느리지?", "어디서 오류가 발생했나?" | "누가 이 리소스를 변경했나?", "루트 계정 로그인 기록은?" |

이 세 가지 서비스를 함께 사용하면 AWS 환경에 대한 가시성을 확보하고, 문제를 신속하게 해결하며, 안전하고 규정을 준수하는 운영 환경을 구축할 수 있습니다.
