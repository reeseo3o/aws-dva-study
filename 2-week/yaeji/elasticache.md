# Redis vs Memcached 요약 비교

| 구분           | Redis                                                      | Memcached                        |
|----------------|------------------------------------------------------------|-----------------------------------|
| 데이터 구조    | 다양한 구조(문자열, 리스트, 셋, 해시, JSON 등) 지원         | 단순 key-value 문자열만 지원      |
| 아키텍처       | 단일 스레드(7.0부터 일부 멀티스레드), 멀티 인스턴스 활용 가능 | 멀티스레드, 멀티코어 효율적 활용  |
| 영속성         | RDB/AOF 통한 영속성, 장애 복구/백업 지원                   | 영속성 없음, 재시작시 데이터 손실 |
| 복제/고가용성  | 마스터-슬레이브 복제, 자동 페일오버, 클러스터링 지원         | 복제/고가용성 기능 제한적         |

## 사용 사례별 권장 사항

- **Redis 사용 권장:**
  - 복잡한 데이터 구조 필요
  - 데이터 영속성 중요
  - 고가용성/자동 페일오버 필요
  - 실시간 분석, 게임 리더보드, 세션 관리 등 고급 기능 필요

- **Memcached 사용 권장:**
  - 단순 key-value 캐싱만 필요
  - 멀티코어/멀티스레드 활용 중요
  - 대규모 노드 확장성 필요
  - 단순한 아키텍처 선호

## AWS ElastiCache 참고

- **ElastiCache for Redis**
  - Redis의 모든 기능 지원
  - 자동 페일오버, 백업, 스케일링 등 관리형 서비스
  - HIPAA, PCI DSS 등 규정 준수

- **ElastiCache for Memcached**
  - Auto Discovery로 클러스터 연결 단순화
  - 관리형 서비스로 운영 부담 감소
  - 기본 캐싱에 최적화

---

**결론:**
- 단순 캐싱 및 멀티스레드 성능이 중요하면 Memcached,
- 그 외 대부분의 경우에는 Redis 사용을 권장합니다.
