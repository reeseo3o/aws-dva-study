# DNS
Domain Name System.

사람이 읽을 수 있는 도메인을 컴퓨터가 읽을 수 있는 실제 IP 주소와 맵핑 해주는 시스템

예를들어 www.naver.com은 그 자체가 실제 IP 주소가 아닙니다.
그럼에도 주소창에 해당 도메인을 입력하면 우린 원하던 네이버의 메인 페이지로 이동할 수 있습니다.

즉 주소창에 입력한 도메인을 실제 IP로 변환해주는 시스템이 존재한다는 이야기입니다.

그리고 이 도메인 네임 시스템을 활용하여 실제 IP를 반환해주는 역할을 하고 있는 서버가 있습니다

이 서버는 DNS (Domain name server) 라고 합니다. 도메인 네임 시스템과 약자가 같지만 엄연히 다른 개념으로 생각해야 합니다.

## 도메인 네임 서버와 시스템의 차이

도메인 네임 시스템은 데이터베이스라고 생각하면 됩니다. 내가 소유한 도메인에 특정 ip를 지정하고 설정을 완료하면
이 두 값이 실제 매핑되어 데이터베이스에 저장되는 시스템입니다.

그리고 도메인 네임 서버는 도메인에 대한 ip주소를 묻는 요청을 받았을 때 도메인 네임 시스템을 활용하여 ip 주소를 반환해주는 역할을 합니다.

## 도메인에 대해서
www.naver.com과 같은 도메인 주소는 .을 기준으로 도메인의 레이어가 분리되어 있습니다.

com -> 최상위 도메인
naver -> 2차 도메인
www -> 서브 도메인


왜 이렇게 나뉘어져 있느냐?
각 레이어의 도메인 네임 서버는 바로 아래 레이어의 DNS 주소만을 가지고 있습니다.

즉 루트 dns는 최상위 도메인의 DNS를 가지고 있습니다.
만약 www.naver.com을 주소창에 입력하면
1. 루트 도메인에게 질의를 합니다. -> www.naver.com의 ip를 알고 있어?
2. 루트 도메인은 하위 도메인의 dns만 알고 있기에 ip 주소는 모르지만 com의 dns가 어디에 있는지는 알아! 하고 대답해줍니다.

그리고 최상위 도메인의 네임 서버는 2차 도메인의 네임 서버를 가지고 있습니다.
1. www.naver.com의 ip를 알고 있어?
2. ip주소는 모르지만 naver의 dns가 어딘지는 알아 하고 대답해줍니다.

2차 도메인의 네임 서버는 권한 네임 서버라고도 불립니다.
서브 도메인은 별도의 네임 서버가 없으며 이 권한 네임 서버에서 같이 관리가 됩니다.

즉, 최종적으로 이 네임 서버에 도메인에 대한 ip 주소를 질의하면 원하는 답을 응답 받을 수 있습니다.

이해가 되셨나요??

## 그래서 Route53 이란?

이 route53이 권한 네임 서버의 역할을 합니다.

route53 콘솔 상에 내가 소유한 도메인과 운영 중인 서버 인스턴스의 ip를 맵핑 해주면

route53은 보유한 도메인 네임 시스템을 통해 도메인, ip 맵핑 정보를 관리하게 되고 후에 이 도메인에 대한 ip 질의를 받으면 실제 ip 주소를 응답해주는 것입니다.

보통 온프레미스 방식의 규모가 큰 기업은 도메인 네임 서버를 직접 구축하기도 합니다.

하지만 클라우드 서비스를 이용하는 우리는 직접 구축할 필요 없이 간편하게 AWS를 활용하여 도메인과 ip를 연결할 수 있게 됩니다.

## Route53 구성요소

### TTL(time to live)
TTL(Time To Live)은 DNS 레코드의 캐싱 시간을 의미합니다.
즉, DNS 응답을 얼마 동안 캐싱할지 결정하는 값입니다.

<동작 방식>
1. 사용자가 www.naver.com에 접속하면, 브라우저와 운영체제(OS)는 DNS 서버에 IP 주소를 요청합니다.
2️. DNS 서버가 www.naver.com → 192.168.1.1을 반환할 때, TTL 값을 함께 전달합니다.
3. 클라이언트는 TTL 동안 해당 IP 주소를 캐싱하여 같은 요청을 반복할 때 DNS 조회를 다시 하지 않음.
4️. TTL이 만료되면, 다시 DNS 조회를 수행하여 최신 정보를 가져옵니다.

### CNAME, Alias
AWS Route 53에서는 CNAME과 ALIAS 레코드를 제공하는데,
둘 다 도메인을 다른 도메인으로 매핑하는 역할을 합니다. 하지만 중요한 차이점이 있습니다.

**CNAME**
CNAME 레코드는 한 도메인을 다른 도메인으로 연결하는 레코드입니다.
www.aaa.com을 bbb.com으로 리디렉션.
즉, www.aaa.com을 요청하면 DNS가 bbb.com을 조회한 후 해당 IP 주소를 반환.

**Alias**
ALIAS 레코드는 특정 AWS 서비스 (CloudFront, S3, ELB 등)와 연결되는 특수 레코드입니다.

레코드 예시
example.com.   0   IN   ALIAS   d1wxyz.cloudfront.net.

example.com이 CloudFront 배포(예: d1wxyz.cloudfront.net)로 직접 연결됨.

## 라우팅 정책

### 단순 라우팅(Simple Routing)
가장 기본적인 라우팅 방식으로, 하나의 도메인에 대해 하나의 IP 주소(또는 엔드포인트)를 설정하는 방식입니다.

<특징>
모든 요청을 하나의 IP 주소(A 레코드) 또는 CNAME 레코드로 연결.
여러 개의 레코드가 있는 경우, 무작위로 선택하여 응답.
장애 감지(Health Check) 기능을 사용할 수 없음.

### 가중치 기반 라우팅(Weighted Routing)
여러 개의 엔드포인트(서버) 중에서 트래픽을 특정 비율(가중치)에 따라 분배하는 방식입니다.

각 엔드포인트(서버)에 대해 가중치를 설정 가능.
가중치가 높은 서버로 더 많은 트래픽이 전달됨.
A/B 테스트나 점진적 배포(Blue/Green Deployment)에 유용.

### 지연 시간 기반 라우팅(Latency-based Routing)
사용자의 위치에서 가장 빠른 응답 속도를 제공하는 서버로 트래픽을 전달하는 방식입니다.

<특징>
AWS가 사용자와 각 리전(Region) 간의 지연 시간(latency)을 측정하여 가장 빠른 서버로 연결.
전 세계 여러 리전에 서버가 있을 때 최적의 응답 속도를 제공.
자동으로 지연 시간이 가장 낮은 리전으로 트래픽을 보냄.
