#RDS

RDS는 Relational Database Service의 약자로 AWS에서 제공해주는 관계형 데이터 베이스 시스템입니다.

콘솔 상에서 필요한 데이터베이스를 선택하고 필요한 설정을 마무리하면 AWS가 자동으로 DB 인스턴스를 생성하여 배포해줍니다.

사용자는 이 DB 인스턴스에 접근할 수 있는 정보를 가지고 직접 내 PC와 연결하거나, DB와 통신이 필요한 서버 인스턴스에 연결을 해줄 수 있습니다.

## DB 유형

AWS RDS가 지원하는 데이터베이스 유형은 아래와 같습니다.

1. postgres

2. mysql

3. 마리아

4. 오라클

5. 마이크로소프트 시퀄 서버

6. ibm db2

7. 오로라 (AWS에서만 지원하는 전용 DB 유형)

## 특징

각각의 데이터베이스는 ec2 인스턴스 내부에 직접 설치하고 배포하여 운영할 수 있습니다.

그렇다면 직접 배포하지 않고 AWS를 통해 배포하는 것과는 어떤 점이 다를까요??

### 프로비저닝 자동화
직접 데이터베이스를 설치하고 배포하려면 별도의 서버 인스턴스를 생성해야 합니다.
이미 서버 애플리케이션을 구성하고 배포까지 완료한 인스턴스가 존재하고 여기에 설치하더라도
데이터베이스 설치, 포트 지정, 리소스 설정 (cpu, 메모리, 스토리지) 등의 관리를 직접 해야합니다.

AWS RDS를 사용하면 콘솔 상에서 이에 대한 설정을 매우 간단히 할 수 있으며, 설정 후 실제 배포는 AWS가 해주므로 매우 간편합니다.

### 운영체제 패칭

데이터베이스를 설치 후 실행하는건 운영체제 위에서 이루어집니다.

즉, 운영체제의 보안 패치와 업데이트가 지속적으로 필요합니다.

RDS를 사용하면 AWS가 이 과정을 자동으로 수행합니다.


### 지속적 백업
RDS는 사용자가 설정한 보존 기간동안 백업을 자동으로 유지해줍니다.
백업 데이터는 S3에 안전하게 저장되며 수동으로 백업에 대한 처리를 할 필요 없어 복원 작업을 쉽게 수행할 수 있습니다.


### 특정 시점 복원
실수로 데이터를 삭제 하는 상황이 발생 시 특정 시간대로 복원할 수 있습니다.


### 대시보드
CloudWatch를 통해 CPU, 메모리, 연결 수, IOPS에 대한 지표를 확인할 수 있습니다.

### 읽기 전용 복제
읽기 부하를 분산시키기 위해 읽기 전용으로 복제본을 생성하여 활용할 수 있습니다.

### 그 외 특징

RDS의 스토리지는 EBS가 제공합니다. -> RDS 인스턴스는 DB 엔진만 설치되며, 해당 RDS 인스턴스로 쿼리 요청이 오면 엔진이 이 쿼리를 해석하고 EBS에 네트워크 통신으로 필요한 데이터 작업을 수행하는 flow

**rds storage auto scaling** -> 임계값을 설정해주면 스토리지 용량을 감지하고 자동 확장해주는 기능입니다.
일정 용량 이상으로는 절대 확장되지 않도록 설정할 수도 있습니다.


## RDS 읽기 전용
RDS 읽기 전용 복제본(Read Replica) 는 기본(primary) 데이터베이스의 데이터를 비동기적으로 복제하여, 읽기 작업을 분산하고 데이터베이스의 부하를 줄이는 데 사용됩니다.

<주요 특징>

비동기 복제
- 기본 DB 인스턴스의 변경 사항이 비동기적으로 리드 레플리카로 복제됨.
- 실시간 동기화가 아니므로, 약간의 지연이 발생할 수 있음.

읽기 부하 분산
- 읽기 쿼리를 리드 레플리카로 보내 읽기 부하를 줄일 수 있음
- 기본 인스턴스는 쓰기 작업에 집중할 수 있음

여러 개의 리드 레플리카 지원
- Amazon RDS는 하나의 기본 인스턴스에 대해 **최대 15개의 리드 레플리카**를 생성할 수 있음.

리드 레플리카를 독립적인 DB로 승격 가능
- 리드 레플리카를 기본 DB 인스턴스로 변경하여 독립적인 데이터베이스로 사용할 수 있음.

## RDS 다중 az 배포
다중 AZ 배포(Multi-AZ Deployment)는 **데이터베이스의 고가용성을 보장하기 위해 RDS 인스턴스를 자동으로 다른 가용 영역(AZ, Availability Zone)에 복제**하는 기능입니다.

이는 장애 조치(Failover)를 자동으로 수행하여 서비스의 중단을 최소화할 수 있도록 합니다.

<주요 특징>

동기식 복제 (Synchronous Replication)
  - 기본(primary) 인스턴스에서 변경된 데이터는 **동기적으로 보조(standby) 인스턴스로 복제**됨.
  - 따라서 보조 인스턴스는 항상 최신 데이터를 유지.

자동 장애 조치 (Automatic Failover)
  - 기본 인스턴스에서 장애가 발생하면 AWS가 자동으로 보조 인스턴스를 승격하여 서비스 지속성을 유지.
  - 애플리케이션에서 데이터베이스 엔드포인트(endpoint)는 유지되므로, 애플리케이션 변경 없이 자동으로 연결됨.

읽기 성능에는 영향 없음
  - 보조 인스턴스는 **장애 발생 전까지 읽기 요청을 처리하지 않음** (즉, 리드 레플리카처럼 사용할 수 없음).
  - 오직 가용성 보장을 위한 기능.

자동 백업 지원
  - 다중 AZ 배포를 설정하면 AWS RDS는 기본 인스턴스와 보조 인스턴스에서 백업을 관리하여 데이터 보호 수준을 높임.

AWS 관리형 기능
  - 데이터 복제, 장애 감지 및 장애 조치는 AWS에서 자동으로 수행.


## AWS Aurora

Amazon Aurora는 AWS에서 제공하는 고성능 관리형 관계형 데이터베이스 서비스입니다.
Aurora는 기존 MySQL 및 PostgreSQL과 호환되면서, RDS보다 성능과 가용성이 향상된 서비스입니다.

<오로라 특징>
-  RDS보다 5배 빠른 MySQL 호환 & 3배 빠른 PostgreSQL 호환 (동일한 디비 유형을 사용하면서도 속도는 훨씬 빠르다는 것)
-  스토리지 자동 확장 (10GB~128TB)
-  6개의 복제본 유지 (3개 가용영역에 걸쳐 복제)
-  자동 복구, 장애 감지 및 페일오버(Failover)
-  Aurora Serverless (사용량에 따라 자동 확장되는 서버리스 옵션 제공)

## RDS 프록시

Amazon RDS Proxy는 데이터베이스 연결을 관리하고 성능을 최적화하는 서비스입니다.

일반적으로 데이터베이스에 대량의 연결 요청이 몰리면 부하가 증가하는 문제가 발생합니다. RDS 프록시는 이 문제를 해결하고 연결을 최적화하는 역할을 합니다.

<기능	설명>
커넥션 풀링: 동일한 DB 연결을 재사용하여 성능 최적화
자동 장애 감지 및 페일오버: RDS/Aurora의 장애 발생 시 자동으로 대체 인스턴스로 전환
보안 강화 (IAM 인증 지원): 애플리케이션이 DB 비밀번호 없이 IAM을 사용해 인증 가능
장애 조치(Failover): 속도 향상	RDS 장애 발생 시 기존 연결을 유지한 채 빠르게 복구
서버리스 지원:	Aurora Serverless와 연동 가능하여 무중단 확장 지원
