# AWS ElastiCache

## 캐시란?

자주 조회되는 데이터를 고성능, 저지연 인메모리 저장소에 보관하여 애플리케이션의 성능을 향상시키는 기술입니다.

## AWS ElastiCache 소개

AWS ElastiCache는 클라우드에서 분산 인메모리 데이터 스토어 또는 캐시 환경을 손쉽게 설정할 수 있도록 AWS가 제공해주는 서비스입니다.

ElastiCache는 두 가지 오픈 소스 인메모리 엔진을 지원합니다:

### Redis
- 다중 가용 영역 지원으로 고가용성 제공
- 읽기 전용 복제본을 통한 읽기 성능 확장
- 자동 백업 및 복원 기능
- AOF(Append-Only File) 지속성으로 데이터 내구성 보장
- 복잡한 데이터 타입 지원 (문자열, 해시, 리스트, 집합, 정렬된 집합 등)
- Pub/Sub 메시징, 트랜잭션, Lua 스크립팅 지원
- 지리 공간 인덱싱 기능

### Memcached
- 단순한 key-value 저장소
- 멀티스레딩 아키텍처로 대규모 노드에서 높은 성능 제공
- 수평적 확장이 용이 (샤딩을 통해 여러 노드에 데이터 분산)
- 복제 및 지속성 기능 없음 (서버리스 버전에서만 백업/복원 지원)
- 단순한 데이터 구조만 지원 (문자열)

## ElastiCache의 사용 사례

다음과 같은 상황에서 ElastiCache는 특히 유용합니다:

1. **데이터베이스 부하 감소**: 자주 액세스하는 데이터를 캐싱하여 데이터베이스의 부하를 줄임
2. **웹 세션 저장**: 사용자 세션 정보를 저장하고 관리
3. **API 응답 캐싱**: 외부 API 호출 결과를 캐싱하여 반복적인 요청 최소화
4. **실시간 분석**: 빠른 데이터 처리와 분석이 필요한 경우
5. **게임 리더보드**: 빠른 정렬과 집계가 필요한 실시간 순위표
6. **인메모리 데이터 처리**: 빠른 읽기/쓰기 성능이 필요한 사용 사례

## 캐싱 패턴

효과적인 캐싱을 위해 다양한 패턴이 사용됩니다:

### 레이지 로딩 (Lazy Loading) / 캐시 어사이드 (Cache-Aside) / 레이지 퍼퓰레이션 (lazy population)

작동 방식:
1. 애플리케이션이 캐시에서 데이터를 요청
2. 캐시에 데이터가 있으면 반환 (캐시 히트)
3. 캐시에 데이터가 없으면 (캐시 미스):
   - 데이터베이스에서 데이터 검색
   - 검색한 데이터를 캐시에 저장
   - 데이터를 애플리케이션에 반환

**장점**:
- 필요한 데이터만 캐싱됨
- 캐시가 삭제되어도 애플리케이션이 계속 작동
- 구현이 상대적으로 간단

**단점**:
- 캐시 미스 시 성능 저하 (3단계 통신 필요)
- 데이터가 최신 상태가 아닐 수 있음 (캐시 무효화 전략 필요)

```python
def get_data(key):
    # 캐시 조회
    data = cache.get(key)
    
    # 캐시 히트
    if data is not None:
        return data
    
    # 캐시 미스
    data = database.query(key)
    
    # 데이터를 캐시에 저장
    cache.set(key, data, ttl=3600)
    
    return data
```

### 라이트 스루 (Write-Through)

작동 방식:
1. 애플리케이션이 데이터베이스에 데이터를 쓰는 작업 수행
2. 데이터베이스 업데이트 후, 동일한 데이터를 캐시에도 업데이트

**장점**:
- 캐시의 데이터가 항상 최신 상태 유지
- 읽기 작업이 항상 최신 데이터 제공

**단점**:
- 쓰기 지연 발생 (데이터베이스와 캐시 모두 업데이트 필요)
- 자주 액세스하지 않는 데이터도 캐싱되어 캐시 공간 낭비
- 구현이 더 복잡함

def update_data(key, value):

### 캐시 제거와 TTL (Time-To-Live)

캐시 데이터를 관리하는 두 가지 주요 방법:

1. **명시적 제거**: 데이터가 업데이트되거나 더 이상 유효하지 않을 때 명시적으로 캐시에서 제거

```python
def invalidate_cache(key):
    # 캐시 제거
    cache.delete(key)
```

2. **TTL(Time-To-Live)**: 캐시된 항목에 만료 시간 설정, 시간이 지나면 자동으로 제거됨

```python
# TTL 설정

```

## 효과적인 ElastiCache 활용 전략

### 1. 적절한 엔진 선택

- **Redis**: 복잡한 데이터 타입, 고가용성, 지속성이 필요한 경우
- **Memcached**: 단순한 객체 캐싱, 수평적 확장성이 중요한 경우

### 2. 적절한 캐싱 전략 선택

- 읽기가 많은 워크로드: 레이지 로딩
- 쓰기 후 즉시 읽기가 필요한 경우: 라이트 스루
- 혼합 패턴: 두 전략을 조합하여 사용

### 3. 캐시 사이징 및 확장

- 적절한 노드 유형 선택 (메모리 크기, CPU, 네트워크 용량)
- 캐시 클러스터 확장 (수직적/수평적 확장)
- CloudWatch 지표를 통한 모니터링 및 자동 확장

### 4. 캐시 무효화 전략

- 적절한 TTL 설정
- 데이터 업데이트 시 캐시 항목 무효화
- 버전 관리 또는 타임스탬프를 통한 일관성 유지

### 5. 보안 고려사항

- VPC 내에서 캐시 클러스터 실행
- 전송 및 저장 중 암호화 활성화 (Redis에서 지원)
- IAM 정책 및 보안 그룹을 통한 접근 제어
