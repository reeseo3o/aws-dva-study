# Amazon S3 고급 기능 요약

## 스토리지 클래스 관리

### 스토리지 클래스 전환
- 다양한 스토리지 클래스 간 자동 전환 가능:
  - 표준 → 표준-IA → One Zone-IA → Glacier → Deep Archive
- 액세스 빈도와 복구 시간에 따라 적절한 클래스 선택하여 비용 최적화

### 수명 주기 규칙
#### 주요 작업 유형
1. **전환 작업**: 객체를 다른 스토리지 클래스로 자동 전환
   - 예: 60일 후 표준-IA로, 6개월 후 Glacier로
2. **만료 작업**: 일정 기간 후 객체 자동 삭제

#### 적용 범위
- 전체 버킷
- 특정 접두사(경로) - 예: `images/`, `logs/`
- 특정 객체 태그 - 예: `project=alpha`

### 📈 최적화 도구: S3 분석
- 표준 및 표준-IA 클래스에 대한 최적 전환 시점 자동 추천
- 일일 업데이트되는 CSV 보고서 제공
- 분석 데이터 확인까지 24-48시간 소요
- 보고서 기반으로 효율적인 수명 주기 규칙 수립 가능

## 🔍 실제 활용 시나리오

### 시나리오 1: 프로필 사진 관리
| 객체 유형 | 초기 저장소 | 전환 규칙 | 목적 |
|:--------:|:----------:|:--------:|:----:|
| 원본 이미지 | 표준 클래스 | 60일 후 Glacier로 자동 전환 | 비용 절감 |
| 썸네일 | One Zone-IA | 60일 후 자동 삭제 | 쉽게 재생성 가능 |

### 시나리오 2: 삭제된 객체 복구
- S3 버전 관리 활성화
- 삭제된 객체는 삭제 마커로 표시됨
- 이전 버전 관리 전략:
  - 최근 버전: 표준 클래스
  - 이전 버전: 표준-IA로 전환 
  - 오래된 버전: Glacier Deep Archive로 이동

## 🔔 이벤트 알림 시스템

### 주요 사용 사례
1. S3에 업로드되는 이미지의 썸네일 자동 생성
2. 특정 확장자를 가진 객체만 필터링하여 처리 (예: `.jpg`, `.pdf`)
3. SNS, SQS, Lambda 등으로 이벤트 전송 가능

### 이벤트 흐름
```
S3 버킷 → Amazon EventBridge → 다양한 AWS 서비스(18종+)
```
- EventBridge에서 다양한 규칙 설정 가능
- 전송 가능한 정보: 메타데이터, 객체 크기, 이름, 태그 등

## S3 성능 최적화 전략

### Baseline Performance
- 첫 번째 바이트 지연 시간: 100-200밀리초
- 접두사(prefix)당 성능:
  - 초당 3,500개의 PUT/COPY/POST/DELETE 요청
  - 초당 5,500개의 GET/HEAD 요청
- 예시: `/folder1/sub1/` 경로에서 초당 3,500개 쓰기와 5,500개 읽기 가능
- **성능 스케일링 팁**: 다수의 접두사 사용시 성능 선형 증가
  - 4개 접두사 사용 → 초당 최대 22,000개 읽기 요청 처리 가능

### Multipart Upload
- 대용량 파일 업로드 효율성 향상을 위한 필수 기능
- 업로드를 병렬화하여 전송 속도를 높이고 대역폭 최대화
- **권장 사용 기준**:
  - 100MB 이상 파일: 권장
  - 5GB 이상 파일: 필수 (S3 단일 업로드 5GB 제한)
- **작동 원리**:
  ```
  대용량 파일 → 작은 청크로 분할 → 병렬 업로드 → S3에서 자동 병합
  ```

### Transfer Acceleration
- AWS 글로벌 엣지 로케이션을 활용한 전송 속도 향상 기능
- 전 세계 어디서든 빠른 업로드/다운로드 가능
- CloudFront의 전 세계 분산 엣지 위치 네트워크 활용

### Byte Range Fetches
- 파일의 특정 바이트 범위만 가져와 병렬 처리하는 고급 기술
- **장점**:
  - 실패 시 더 작은 범위만 재시도 가능하여 복원력 향상
  - 병렬 다운로드를 통한 속도 향상
- **활용 사례**:
  - 파일 헤더만 먼저 읽어 메타 정보 확인 (예: 파일 첫 50바이트)
  - 대용량 파일에서 필요한 부분 데이터만 선택적으로 가져오기
  - 동영상 스트리밍의 특정 부분만 로드

## 🏷️ S3 객체의 태그 및 메타데이터 활용

### 메타데이터
- 객체에 연결된 키-값 쌍 형태의 추가 정보
- **사용자 정의 메타데이터**:
  - 이름은 `x-amz-meta-` 접두사로 시작해야 함 (AWS 시스템 메타데이터와 구분)
  - 객체 검색 시 함께 조회 가능
- **예시**:
  - AWS 제공 메타데이터: 콘텐츠 길이(7.5kB), 콘텐츠 타입(html)
  - 사용자 정의 메타데이터: `x-amz-meta-origin: paris`, `x-amz-meta-author: jsmith`

### 객체 태그
- S3 객체에 지정할 수 있는 키-값 쌍 태그 (최대 10개)
- **활용 사례**:
  - 세부적인 접근 권한 제어
  - 특정 태그가 있는 객체에만 액세스 허용
  - 수명 주기 규칙 적용 기준
  - S3 분석 결과 그룹화 (예: `Project: Blue`, `PHI: True`, `Department: Marketing`)

### 검색 제한사항 및 해결책
- **중요 제한사항**: S3에서는 메타데이터나 태그로 직접 검색/필터링 불가능
- **실용적 해결책**:
  - DynamoDB와 같은 외부 데이터베이스에 인덱스 구축
  - S3 객체 생성/수정 시 모든 메타데이터와 태그를 DynamoDB에 함께 저장
  - DynamoDB에서 검색 후 결과로 찾은 S3 객체 키로 원본 파일 접근

> 💡 **시험 포인트**: S3 객체 메타데이터/태그 검색을 위한 DynamoDB 인덱싱 아키텍처는 DVA 시험에 자주 출제되는 내용입니다.

## 📝 핵심 시험 포인트
- 스토리지 클래스 전환은 비용 최적화의 핵심 (표준 → IA → Glacier)
- 수명 주기 규칙은 전체 버킷, 접두사, 태그별로 적용 가능
- S3 성능: 접두사당 3,500 쓰기/5,500 읽기 요청/초
- 대용량 파일(100MB+)은 Multipart Upload 사용 필수 
- S3 메타데이터/태그 검색은 DynamoDB와 같은 외부 인덱스 필요
- 이벤트 알림은 EventBridge를 통해 다양한 AWS 서비스와 연동 가능
