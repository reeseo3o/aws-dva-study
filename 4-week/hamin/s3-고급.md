# S3 고급

### 객체 수명 주기 관리

S3 수명주기 정책(Lifecycle Policy)은 객체를 다음과 같은 조건에 따라 **자동으로 다른 스토리지 클래스로 전환**하거나 **삭제**하는 규칙을 설정할 수 있게 해줍니다.

구성요소

- **Transition (전환)**: 객체를 **비용이 낮은 스토리지 클래스로 이동**
    
    예: `STANDARD → INTELLIGENT_TIERING → GLACIER`
    
- **Expiration (만료)**: 객체를 **자동 삭제**
- **NoncurrentVersion Transition / Expiration**: 버전 관리 중인 객체의 이전 버전을 전환/삭제

### S3 애널리틱스

S3 애널리틱스는 **객체의 접근 패턴을 분석해서**, 어떤 객체를 더 저렴한 스토리지 클래스로 이동시킬 수 있을지 **통계적으로 추천**해주는 기능입니다.

- 객체 접근 패턴을 **일정 기간(최대 2년)** 분석
- `STANDARD_IA`, `INTELLIGENT_TIERING` 으로의 전환을 추천
- 분석 데이터는 **CSV로 저장**, **S3 콘솔에서 시각화**
- 주기적으로 갱신 (보통 하루 단위)

➡️ **수명주기 정책을 만들기 전에 S3 애널리틱스를 통해 분석**하면, 불필요한 전환/삭제를 방지하고 정확한 정책을 만들 수 있음.

### S3 이벤트 알림

S3 버킷에 **객체 생성, 삭제 등 이벤트**가 발생했을 때 자동으로 알림을 보내는 기능입니다.

**연동 가능한 대상**:

- **Amazon SNS**
- **Amazon SQS**
- **AWS Lambda**

→ 버킷 단위로 설정

→ prefix/tag 필터링 가능

### S3 성능

기본적으로 아마존 s3는 매우 높은 요청 수로 자동으로 스케일링 된다.

첫 번째 바이트를 가져오는데 100~200밀리초로 빠르게 가져올 수 있다.

버킷 내에서 prefix당 초당 3,500개의 put, copy, post, delete를 하거나

5,500개의 get 또는 head가 가능하다.

위의 초당 n개 요청 조건은 접두사가 나눠지면 접두사 마다 적용된다. (베리베리 고성능)


### 성능 최적화

멀티파트 업로드

→ 업로드를 병렬화 하는 방법

→ 파일을 작은 덩어리로 나눈 후 S3에 병렬로 업로드한다.

100MB 이상에선 권장

5GB 이상에선 필수

S3 Transfer Acceleration

업로드 및 다운로드를 위한 s3 전송 가속화

→ 파일을 AWS 엣지 위치로 전송하여 전송 속도를 높인다

→ 해당 데이터가 대상 지역의 S3 버킷으로 전달된다.

핵심: 외부 네트워크로만 s3 버킷에 접근하느냐 vs 가장 가까운 aws의 엣지까지는 외부 인터넷으로 접근하되 거기 부턴 백본망을 이용하느냐의 차이

전송 가속화는 멀티파트 업로드와 호환됩니다.

S3 Byte-Range Fetches

범위 가져오기라고 하며, 특정 바이트 범위를 가져와 가져오기를 병렬화 한다.

특정 바이트 범위를 가져오는데 실패해도 더 작은 범위의 바이트 가져오리고 재시도 가능

다운로드 속도를 높일 수 있음

사용 사례로 파일의 일부만 검색하는 용도도 있음

S3에서 파일의 처음 50바이트가 헤더라는 것을 알고 파일에 대한 정보를 제공하면 헤더를 발행할 수 있다.
