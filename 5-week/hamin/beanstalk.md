# Elastic Beanstalk

애플리케이션을 배포하는 데 있어 개발자 중심의 관점을 제공합니다.  
하나의 인터페이스에서 EC2, ASG, ELB, RDS와 같은 모든 구성 요소를 재사용할 수 있으며, 이러한 모든 것을 자동으로 배포해 주는 관리형 서비스입니다.

Elastic Beanstalk는 용량 프로비저닝, 로드 밸런서 구성, 자동 확장, 애플리케이션 안정성 모니터링과 인스턴스 구성 등을 처리할 수 있습니다.  
**개발자의 유일한 책임은 코드 자체입니다.**  
구성 요소에 대한 제어는 가능하지만 Beanstalk이 단일 인터페이스에서 제공합니다.

---

## 구성 요소

### 애플리케이션
- 환경, 버전, 구성 등과 같은 Beanstalk 구성 요소의 모음
- 애플리케이션 버전은 코드의 반복 버전 (v1, v2, v3 등)
- 환경은 특정 애플리케이션 버전을 실행하는 리소스의 모음이며, 한 환경에서는 하나의 버전만 사용 가능
- 개발, 테스트, 프로덕션 등 다양한 환경 생성 가능

---

## 배포 정책

| 배포 정책 | 로드 밸런싱된 환경 | 단일 인스턴스 환경 | 레거시 Windows Server 환경 |
| --- | --- | --- | --- |
| 한 번에 모두 (All at once) | ✅ | ✅ | ✅ |
| 롤링 (Rolling) | ✅ | ❌ | ✅ |
| 추가 배치를 사용한 롤링 | ✅ | ❌ | ❌ |
| 변경 불가능 (Immutable) | ✅ | ✅ | ❌ |
| 트래픽 분할 (Traffic Splitting) | ✅ | ❌ | ❌ |

### 한 번에 모두
- **장점**: 빠른 배포 가능
- **단점**: 무중단 배포 불가

### 롤링
- **장점**: 서비스 중단 없이 배포 가능
- **단점**: 오래 걸릴 수 있음
- ❌ 단일 인스턴스 환경에서는 불가

### 추가 배치를 사용한 롤링
- 기존 인스턴스 외 추가 인스턴스 사용
- **장점**: 서비스 안정성 증가
- **단점**: 추가 비용 발생
- ❌ 단일 인스턴스 환경에서는 불가

### 변경 불가능 (Immutable)
- 기존 인스턴스 유지, 새 인스턴스에 배포 후 트래픽 전환
- **장점**: 안정적이고 롤백 쉬움
- ✅ 단일 인스턴스 환경에서도 사용 가능

### 트래픽 분할 (Traffic Splitting)
- ALB 활용해 트래픽 점진적으로 분배
- Immutable과 유사하나 트래픽을 점진적으로 전환
- ❌ 단일 인스턴스 환경 불가

## Elastic Beanstalk CLI

CLI 명령어를 통해 쉽게 배포 가능

- `eb create`
- `eb status`
- `eb health`
- `eb events`
- `eb logs`
- `eb open`
- `eb deploy`
- `eb config`
- `eb terminate`

> 개발자 시험에서는 명령어를 외울 필요는 없음

배포 시 플랫폼을 명확히 지정해야 함 (ex. Python, Node.js 등)

---

## Beanstalk 수명주기 정책

- 최대 1000개 버전 저장 가능
- 오래된 버전 삭제하지 않으면 새 버전 배포 불가
- **삭제 정책**
  - 시간 기준 삭제
  - 공간 기준 삭제
- 현재 사용 중인 버전은 삭제되지 않음
- S3에서 소스 번들 삭제 방지 옵션 존재
- 수명주기 정책은 Beanstalk 인터페이스에서 설정 가능

## Beanstalk Extensions (확장)

- 배포 zip 파일에 `.ebextensions/` 폴더 포함 가능
- YAML 또는 JSON 형식의 `.config` 파일 사용
- 콘솔에서 설정하던 모든 것들을 코드로 관리 가능
- 리소스 추가 가능 (예: ElastiCache, RDS 등)
- 추가된 리소스는 Beanstalk 환경 삭제 시 함께 삭제됨

작동 원리 및 CloudFormation
Beanstalk는 내부적으로 CloudFormation 기반

.ebextensions 내의 리소스는 CloudFormation 리소스 형태로 동작

콘솔 UI로 설정 불가한 항목도 코드 기반으로 구성 가능

## Beanstalk 환경 복제 (Cloning)
기존 환경을 동일 구성으로 복제 가능

배포 버전이 있는 경우 테스트 환경 구성 시 유용

원본 환경의 설정은 유지되나, DB 데이터는 복제되지 않음

## Beanstalk 마이그레이션
### 로드 밸런서 유형 변경
환경 생성 후에는 로드밸런서 유형 변경 불가

마이그레이션 필요
- 동일한 설정으로 새 환경 생성 (로드밸런서 유형만 변경)

- CNAME 교체 또는 Route53 DNS 업데이트


### RDS 분리
RDS를 Beanstalk에서 분리해서 사용하는 것이 프로덕션에 적합

이유: Beanstalk 환경 삭제 시 RDS도 삭제될 수 있음

방법
- RDS 스냅샷 생성
- RDS 콘솔에서 삭제 방지 설정
- 새 Beanstalk 환경 구성 (RDS 제외)
- 환경 변수 등을 통해 기존 RDS 연결
- CNAME 교체 또는 블루그린 배포
