# AWS EC2 인스턴스 스토리지 가이드

AWS에서 EC2 인스턴스를 사용할 때, 데이터를 저장하는 방법은 매우 중요합니다. AWS에서는 EBS (Elastic Block Store)와 EFS (Elastic File System) 두 가지 주요 스토리지 옵션을 제공합니다.

EBS와 EFS의 개념, 유형, 기능, 차이점 등을 자세히 설명하며, 어떤 상황에서 어떤 옵션을 선택해야 하는지 실무적인 관점에서 정리해보겠습니다.

```
                  +-----------------+
                  |   AWS Storage   |
                  +-----------------+
                 /                   \
                /                     \
+---------------+                   +---------------+
|  Block Store  |                   |  File System  |
|     (EBS)     |                   |     (EFS)     |
+---------------+                   +---------------+
|               |                   |               |
| • 1:1 연결     |                   | • 다중 연결     |
| • 단일 AZ      |                   | • 다중 AZ      |
| • 고정 크기     |                   | • 자동 확장     |
+---------------+                   +---------------+
```

## EBS (Elastic Block Store) - EC2의 블록 스토리지

### EBS란?
EBS는 AWS에서 제공하는 **블록 스토리지(Block Storage) 서비스**입니다.
쉽게 말해, **EC2 인스턴스의 영구적인 디스크 공간**을 제공하는 서비스입니다.

```
    +---------------+       +---------------+
    |               |       |               |
    |  EC2 Instance +-------+ EBS Volume    |
    |               |       |               |
    +---------------+       +---------------+
        하나의 EC2 인스턴스에 연결된 EBS 볼륨
        (다른 EC2로 옮길 수 있지만, 동시에 여러 EC2와 연결 불가능)
```

### EBS 주요 특징

- **EC2 인스턴스와 분리 가능** (필요할 때 다른 인스턴스에 연결 가능)
- **특정 가용 영역(AZ) 내에서만 존재** (다른 AZ로 이동하려면 스냅샷 필요)
- **볼륨 크기와 IOPS를 사전에 지정해야 함**
- **프로비저닝한 용량에 따라 비용이 청구됨**
- **EC2 인스턴스 종료 후에도 데이터 유지 가능**
- **일반적인 하드 드라이브와 유사하지만, 네트워크를 통해 연결됨** (즉, 물리적으로 인스턴스 내부에 저장되는 것이 아님)

### EBS 볼륨 유형
AWS는 다양한 사용 사례를 지원하기 위해 6가지 EBS 볼륨 타입을 제공합니다.
각 볼륨 타입은 성능, 가격, 사용 목적에 따라 다릅니다.

```
+----------------------+    +----------------------+
|     SSD 기반 볼륨      |    |     HDD 기반 볼륨     |
+----------------------+    +----------------------+
| ┌------------------┐ |    | ┌------------------┐ |
| | gp2/gp3: 범용 SSD | |    | | st1: 처리량 최적화  | |
| | • 일반 워크로드     | |    | | • 빅데이터        | |
| | • 부팅 볼륨        | |    | | • 로그 처리       | |
| └------------------┘ |    | └------------------┘ |
|                      |    |                      |
| ┌------------------┐ |    | ┌------------------┐ |
| | io1/io2: 고성능   | |    | | sc1: 콜드 HDD    | |
| | • 데이터베이스     | |    | | • 아카이브        | |
| | • 낮은 지연시간    | |    | | • 백업 데이터     | |
| └------------------┘ |    | └------------------┘ |
+----------------------+    +----------------------+
     성능 ↑  비용 ↑            성능 ↓  비용 ↓
```

| 볼륨 유형 | 설명 | 용도 |
|-----------|------|------|
| **gp2/gp3 (SSD)** | 범용 SSD, 저비용 | OS 부팅, 웹 서버, 일반적인 애플리케이션 |
| **io1/io2 (SSD)** | 고성능 SSD, 높은 IOPS | 데이터베이스, 고처리량 워크로드 |
| **st1 (HDD)** | 처리량 최적화 HDD | 빅데이터, 로그 분석 |
| **sc1 (HDD)** | 콜드 HDD (저렴) | 장기 데이터 보관 |

### gp2 vs gp3 차이점
AWS에서는 범용 SSD 볼륨으로 **gp2**와 **gp3**을 제공합니다.

| | **gp2** | **gp3** |
|---|-------|--------|
| **IOPS** | 자동 증가 | 수동 설정 가능 |
| **최대 IOPS** | 16,000 | 16,000 |
| **처리량** | 볼륨 크기에 따라 증가 | 최대 1,000MB/s |
| **비용** | 상대적으로 비쌈 | 더 저렴 |

#### gp3가 개선된 점
- gp3는 **IOPS와 처리량을 독립적으로 설정 가능** (gp2는 크기에 따라 자동 증가)
- **비용이 더 저렴**하면서도 고성능 제공

```
    gp2 볼륨                    gp3 볼륨
+----------------+       +----------------+
|                |       |                |
| 크기: 1000GB    |       | 크기: 1000GB    |
|                |       |                |
| IOPS: 3000     |  vs   | IOPS: 16000    |
| (크기에 비례)    |       | (독립적 설정)    |
|                |       |                |
| 처리량: 250MB/s |       | 처리량: 1000MB/s|
| (크기에 비례)    |       | (독립적 설정)    |
+----------------+       +----------------+
```

### EBS 스냅샷 (EBS Snapshots)
EBS 스냅샷은 **EBS 볼륨의 특정 시점 백업**을 의미합니다.
**EBS 스냅샷을 활용하면 다른 가용 영역(AZ)이나 리전으로 데이터를 복사할 수 있습니다.**

```
   +---------------+     스냅샷 생성     +---------------+
   |               |  ---------------→  |               |
   |  EBS Volume   |                    |  EBS Snapshot |
   |  (us-east-1a) |  ←---------------  |  (S3 저장)    |
   +---------------+    새 볼륨 생성     +---------------+
                              ↓
                       +---------------+
                       |  EBS Volume   |
                       |  (us-east-1b) |
                       +---------------+
```

#### EBS Snapshot 주요 기능

1. **Snapshot Archive**
   - **75% 저렴한 저장소**에 스냅샷을 보관
   - 복구 시간: **24~72시간**
   - 장기 데이터 보관에 적합

2. **Recycle Bin for Snapshots**
   - **스냅샷을 영구 삭제하지 않고 휴지통에 보관**
   - 보관 기간: **1일 ~ 1년**
   - 실수로 삭제하는 경우 대비 가능

3. **Fast Snapshot Restore (FSR)**
   - **스냅샷을 즉시 사용할 수 있도록 준비됨**
   - 볼륨 생성 후 대기 없이 바로 사용 가능
   - **비용이 높음** (빠른 복원이 필요할 때만 사용)

```
                   EBS 스냅샷 생명주기
+---------------+      +---------------+      +---------------+
|  표준 스냅샷    | ---> |  스냅샷 아카이브  | ---> |  영구 삭제     |
+---------------+      +---------------+      +---------------+
       |                      ^                      ^
       |                      |                      |
       v                      |                      |
+---------------+             |                      |
|  휴지통        | -----------+----------------------+
+---------------+
 (1일~1년 보관)
```

### EBS 다중 연결 기능 (Multi-Attach)
- **io1, io2 볼륨만 지원**
- **최대 16개의 EC2 인스턴스에 연결 가능**
- **클러스터형 애플리케이션에서 유용** (예: **Teradata, Oracle RAC**)
- **가용성이 높아지고 데이터 일관성 유지 가능**

```
                             +---------------+
                             |               |
                        +----+ EC2 Instance 1|
                        |    |               |
                        |    +---------------+
                        |
    +---------------+   |    +---------------+
    |               |   |    |               |
    | EBS io1/io2   +---+----+ EC2 Instance 2|
    | (Multi-Attach)|   |    |               |
    +---------------+   |    +---------------+
                        |
                        |    +---------------+
                        |    |               |
                        +----+ EC2 Instance 3|
                             |               |
                             +---------------+
```

## EFS (Elastic File System) - 공유 네트워크 파일 시스템

### EFS란?
EFS는 **AWS에서 제공하는 관리형 네트워크 파일 스토리지(NFS) 서비스**입니다.
쉽게 말해, 여러 EC2 인스턴스에서 **동시에 접근 가능한 파일 시스템**을 제공하는 서비스입니다.

```
                     +-----------------+
                     |                 |
+---------------+    |    +---------------+
|               |    |    |               |
| EC2 Instance 1+----+----+ EFS File      |
|               |    |    | System        |
+---------------+    |    |               |
                     |    | (여러 AZ에     |
+---------------+    |    | 걸쳐 동작)     |
|               |    |    |               |
| EC2 Instance 2+----+    +---------------+
|               |    |
+---------------+    |
                     |
+---------------+    |
|               |    |
| EC2 Instance 3+----+
|               |
+---------------+
```

### EFS 주요 특징
- **자동 확장** (데이터가 늘어나면 자동 확장)
- **여러 가용 영역(AZ)에서 동시에 접근 가능**
- **EBS보다 3배 비쌈** (고성능)
- **Linux 전용** (Windows 미지원)
- **POSIX 호환 파일 시스템 지원**
- **EBS와 달리 미리 크기를 설정할 필요 없음**

### EFS 성능 모드

| 모드 | 설명 |
|------|------|
| **General Purpose** | 기본 성능 모드 (웹서버, CMS) |
| **Max I/O** | 높은 처리량이 필요한 워크로드 (빅데이터) |

```
            EFS 성능 모드
    +-------------------------+
    |                         |
    |   +---------------+     |     +---------------+
    |   | General       |     |     | Max I/O       |
    |   | Purpose       |     |     |               |
    |   +---------------+     |     +---------------+
    |   | • 낮은 지연 시간 |     |     | • 높은 처리량  |
    |   | • 메타데이터 작업 |     |     | • 메타데이터  |
    |   |   성능 최적화   |     |     |   병목 현상 가능|
    |   | • 대부분 워크로드|     |     | • 빅데이터 등  |
    |   |   적합         |     |     |   대규모 병렬  |
    |   |               |     |     |   워크로드 적합 |
    |   +---------------+     |     +---------------+
    +-------------------------+
```

### EFS 스토리지 클래스

| 스토리지 계층 | 설명 |
|-------------|------|
| **Standard** | 다중 AZ, 높은 가용성 |
| **EFS-IA (Infrequent Access)** | 자주 접근하지 않는 데이터 저장 (비용 절감) |

### EFS 비용 절감 방법
EFS는 비용이 상대적으로 높기 때문에, 비용 절감을 위해 다음 기능을 활용할 수 있습니다.

- **EFS-IA (Infrequent Access) 활용**
  - **자주 사용하지 않는 데이터를 IA로 자동 이동** → 비용 절감 가능
- **라이프사이클 관리 설정**
  - 특정 기간 동안 사용되지 않은 데이터를 **자동으로 저렴한 스토리지로 이동**

```
   EFS 라이프사이클 관리

 자주 액세스하는 파일 ◀───────┐
         │                    │
         ▼                    │
  +-------------+       +-------------+
  |  Standard   |       |  Infrequent |
  |  Storage    |       |  Access (IA)|
  +-------------+       +-------------+
         │                     ▲
         │                     │
         └────────────────────┘
             라이프사이클 정책
        (N일 동안 미사용 파일은 IA로 이동)
```

## EBS vs EFS 비교
EBS와 EFS는 **사용 방식과 특징이 완전히 다릅니다.**
사용하려는 애플리케이션에 따라 적절한 스토리지를 선택해야 합니다.

```
+------------------------+     +------------------------+
|                        |     |                        |
|     EBS (블록 스토리지)  |     |    EFS (파일 시스템)    |
|                        |     |                        |
+------------------------+     +------------------------+
|                        |     |                        |
| • 하나의 EC2 인스턴스만   |     | • 여러 EC2 인스턴스 연결  |
|   연결 가능              |     |   가능                  |
|                        |     |                        |
| • 특정 AZ에 고정         |     | • 여러 AZ에서 사용 가능    |
|                        |     |                        |
| • 고정 용량 (수동 확장)   |     | • 자동 확장              |
|                        |     |                        |
| • 낮은 지연 시간         |     | • 약간 높은 지연 시간      |
|                        |     |                        |
| • 높은 IOPS 지원        |     | • 높은 처리량             |
|                        |     |                        |
| • 용량 기반 요금          |     | • 사용량 기반 요금        |
|                        |     |                        |
+------------------------+     +------------------------+
|                        |     |                        |
|     적합한 사용 사례      |     |     적합한 사용 사례      |
|                        |     |                        |
| • 데이터베이스           |     | • 웹 서버 콘텐츠         |
| • 부팅 볼륨             |     | • 컨테이너 공유 데이터    |
| • 고성능 워크로드         |     | • 빅데이터 분석         |
| • 단일 인스턴스 접근      |     | • 콘텐츠 관리 시스템     |
|                        |     |                        |
+------------------------+     +------------------------+
```

| 항목 | EBS | EFS |
|------|--------|--------|
| 연결 가능 인스턴스 | 한 번에 1개 | 여러 개 |
| 사용 가능한 AZ | 특정 AZ에 고정 | 여러 AZ에서 사용 가능 |
| 백업 방법 | 스냅샷 필요 | 기본 제공 |
| 확장성 | 수동 조절 필요 | 자동 확장 |
| 비용 | 사용량 기준 | 3배 비쌈 |
| 사용 사례 | 데이터베이스, VM 디스크 | 공유 파일 시스템 |

### 정리
- EBS → EC2 인스턴스 하나에 연결되는 디스크형 스토리지
  - 데이터베이스, 애플리케이션 스토리지 등에 적합
- EFS → 여러 EC2 인스턴스에서 동시에 사용할 수 있는 파일 스토리지
  - 다중 서버에서 공유해야 하는 애플리케이션 (웹서버, 빅데이터 분석)에 적합

### 결론
- **EBS는 블록 스토리지로, 한 번에 하나의 EC2에 연결되는 디스크형 저장소**
- **EFS는 네트워크 파일 시스템으로, 여러 EC2에서 동시에 접근 가능**

사용 목적에 따라 적절한 스토리지를 선택하면 비용을 절감하고 성능을 최적화할 수 있습니다.
