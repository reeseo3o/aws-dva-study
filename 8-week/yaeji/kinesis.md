# Amazon Kinesis Data Streams (KDS)

## 📌 기본 개념

Amazon Kinesis Data Streams(KDS)는 확장성과 내구성이 뛰어난 실시간 스트리밍 데이터 수집 및 처리 서비스입니다.

초당 기가바이트급의 데이터를 수집 가능하며, 수십만 개의 소스에서 데이터를 지속적으로 수집할 수 있습니다.

### 주요 데이터 소스 및 사용 사례
- 센서 데이터
- 클릭스트림
- 로그 데이터
- 금융 거래 데이터
- 소셜 미디어 피드
- IT 로그
- 위치 추적 이벤트
- 데이터베이스 이벤트 스트림

### 실시간 활용
- 실시간 대시보드
- 실시간 이상 탐지
- 동적 가격 책정
- 밀리초 단위 데이터 제공

## 📌 핵심 구성 요소

| 구성요소 | 설명 |
|---------|------|
| Stream | 데이터가 저장되는 논리적 파이프라인 |
| Shard | 처리 단위 (샤드 수에 따라 처리량 결정) |
| Record | 실제 데이터 단위 (데이터 blob + 파티션 키 등) |
| Producer | 데이터를 스트림으로 보내는 클라이언트 |
| Consumer | 데이터를 스트림에서 읽는 애플리케이션 (예: Lambda, EC2 등) |

## 📌 중요 기능/특징

### 샤드 성능
- **처리량 확장**: 샤드를 추가하면 처리량 증가
- **샤드당 용량**:
  - 쓰기: 1MB/s
  - 읽기: 2MB/s
  - 최대 1000 레코드/초

### 데이터 처리 특성
- **데이터 보관**: 기본 24시간, 최대 7일(옵션 설정 시)
- **처리 보장**: Exactly-once ❌, At-least-once ⭕ (중복 처리 가능성 있음)
- **순서 보장**: 같은 파티션 키 내에서는 순서 보장

## 📌 소비 방식

### 1. Kinesis Client Library (KCL)
- 샤드 병렬 읽기 지원
- 체크포인팅 기능 제공

### 2. AWS Lambda
- 이벤트 기반 처리

### 3. Kinesis Data Firehose
- 자동으로 데이터를 다음 서비스로 전송:
  - Amazon S3
  - Amazon Redshift
  - Amazon Elasticsearch
  - 기타 지원 서비스

## 📌 비교 포인트 (시험 단골)

| 비교 항목 | Kinesis Data Streams | Kinesis Data Firehose |
|----------|---------------------|----------------------|
| 처리 방식 | 실시간 스트리밍 | 실시간 + 자동 배치 |
| 처리 제어 | 커스텀 가능 | 완전 관리형 |
| 대상 | 개발자 중심 | 분석 도구 연동 중심 |
| 저장소 전송 | 수동/코딩 필요 | 자동으로 S3 등으로 전송 |

## 📌 샤드(Shard) 상세 설명

### 1. 샤드의 기본 개념
- **정의**: Kinesis 스트림에서 데이터를 저장하고 처리하기 위한 기본 처리 단위
- **비유**: Kinesis 스트림을 고속도로라고 하면, 샤드는 각각의 차선과 같음
- **역할**: 데이터의 수집, 저장, 소비(읽기)를 담당

### 2. 샤드의 처리 용량
| 기능 | 용량 제한 |
|------|-----------|
| 쓰기(Input) | 초당 1MB 또는 1,000 레코드 |
| 읽기(Output) | 초당 2MB |

### 3. 샤드의 주요 특징
| 특징 | 설명 |
|------|------|
| 병렬 처리 | 각 샤드는 독립적으로 동작하며 병렬 처리 가능 |
| 순서 보장 | 동일한 파티션 키를 가진 데이터는 순서 보장 (FIFO) |
| 확장성 | 샤드 분할을 통한 처리량 증가 가능 |
| 비용 효율성 | 샤드 병합을 통한 비용 최적화 가능 |

### 4. 샤드 관리 작업
#### 4.1 샤드 분할 (Split)
- **목적**: 처리량 증가가 필요할 때
- **결과**: 1개 샤드 → 2개 샤드
- **사용 시점**:
  - 데이터 처리량이 증가할 때
  - 처리 지연이 발생할 때
  - 새로운 데이터 소스가 추가될 때

#### 4.2 샤드 병합 (Merge)
- **목적**: 비용 최적화
- **결과**: 2개 샤드 → 1개 샤드
- **사용 시점**:
  - 데이터 처리량이 감소할 때
  - 비용 절감이 필요할 때
  - 리소스 최적화가 필요할 때

### 5. 실무 활용 사례
#### 5.1 실시간 데이터 처리
- **주식 거래 데이터**: 대량의 실시간 거래 데이터 처리
- **사용자 행동 분석**: 클릭스트림, 페이지뷰 등의 실시간 분석
- **IoT 센서 데이터**: 다수의 IoT 디바이스에서 발생하는 센서 데이터 수집

#### 5.2 로그 수집 및 분석
- **애플리케이션 로그**: 다수의 서버에서 발생하는 로그 실시간 수집
- **보안 모니터링**: 보안 이벤트 및 알림의 실시간 처리
- **시스템 모니터링**: 시스템 메트릭 실시간 수집 및 분석

### 6. 모니터링 및 최적화
#### 6.1 주요 모니터링 지표
- **GetRecords.IteratorAgeMilliseconds**: 레코드 처리 지연 시간
- **WriteProvisionedThroughputExceeded**: 쓰기 용량 초과 횟수
- **ReadProvisionedThroughputExceeded**: 읽기 용량 초과 횟수

#### 6.2 최적화 전략
- **파티션 키 설계**: 데이터 분산을 위한 효율적인 파티션 키 설정
- **샤드 수 조정**: 처리량에 따른 적절한 샤드 수 유지
- **배치 처리**: GetRecords API 호출 최적화를 위한 배치 크기 조정

### 7. 비용 고려사항
- **샤드 시간당 비용**: 각 샤드에 대해 시간당 요금 부과
- **데이터 보관**: 기본 24시간, 최대 7일까지 연장 가능 (추가 비용)
- **API 호출 비용**: Put, Get 등 API 호출에 대한 요금

## 📌 Lambda와 Kinesis Data Streams 통합

### 1. 기본 아키텍처
- **이벤트 소스 매핑**: Lambda가 Kinesis 스트림을 폴링하여 데이터를 가져옴
- **처리 방식**: 샤드별로 독립적인 Lambda 인스턴스가 실행됨
- **동시성 모델**: 샤드 수가 최대 Lambda 동시성을 결정

### 2. 동시성과 처리 특성
| 항목 | 설명 |
|------|------|
| 최대 동시성 | 활성 샤드 수와 동일 |
| 처리 순서 | 샤드 내에서 순차 처리 보장 |
| 배치 처리 | BatchSize 파라미터로 한 번에 처리할 레코드 수 지정 |
| 처리 시간 | Lambda 타임아웃 최대 15분 |

### 3. 주요 설정 파라미터
#### 3.1 BatchSize
- **의미**: 단일 Lambda 호출에서 처리할 최대 레코드 수
- **기본값**: 100
- **범위**: 1 - 10,000
- **고려사항**:
  - 큰 값: 처리 효율성 증가, 지연 시간 증가
  - 작은 값: 더 빠른 처리, 더 많은 Lambda 호출

#### 3.2 ParallelizationFactor
- **의미**: 단일 샤드를 동시에 처리할 Lambda 인스턴스 수
- **기본값**: 1
- **범위**: 1 - 10
- **사용 시점**: 처리 지연이 발생할 때 병렬성 확보

### 4. 성능 최적화
#### 4.1 처리량 증가 방법
- **샤드 분할**: 더 많은 병렬 처리를 위해 샤드 수 증가
- **BatchSize 조정**: 단일 호출당 처리량 최적화
- **ParallelizationFactor 증가**: 샤드당 병렬 처리 수준 증가

#### 4.2 일반적인 문제와 해결책
| 문제 | 해결 방안 |
|------|-----------|
| 처리 지연 | BatchSize 감소 또는 ParallelizationFactor 증가 |
| 높은 비용 | BatchSize 증가로 Lambda 호출 수 감소 |
| 순서 중요 | ParallelizationFactor를 1로 유지 |
| 처리량 부족 | 샤드 분할로 병렬성 확보 |

### 5. 모니터링 및 문제 해결
#### 5.1 주요 모니터링 지표
- **Iterator Age**: 처리 지연 시간
- **ProvisionedThroughputExceeded**: 처리량 초과 횟수
- **Lambda Invocation Errors**: 함수 호출 실패
- **Lambda Duration**: 함수 실행 시간

#### 5.2 일반적인 오류와 대처
| 오류 | 원인 | 대처 방안 |
|------|------|-----------|
| Throttling | Lambda 동시성 제한 초과 | 동시성 제한 증가 또는 BatchSize 조정 |
| Timeout | 처리 시간 초과 | BatchSize 감소 또는 함수 최적화 |
| Iterator Age 증가 | 처리 지연 발생 | 병렬성 증가 또는 처리 로직 최적화 |

### 6. 비용 최적화 전략
#### 6.1 Lambda 비용 최적화
- **BatchSize 최적화**: 더 큰 배치로 호출 수 감소
- **메모리 할당**: 처리 시간과 메모리 사용량 밸런스
- **코드 효율성**: 불필요한 처리 제거

#### 6.2 Kinesis 비용 최적화
- **샤드 관리**: 필요한 만큼만 샤드 유지
- **데이터 보관**: 필요한 기간만큼만 보관
- **API 호출**: 배치 처리로 API 호출 최소화

### 7. 실제 시나리오 예시
#### 7.1 고성능 처리 필요 시
```python
# Lambda 함수 설정
BatchSize: 10000
ParallelizationFactor: 10
MemorySize: 1024MB
Timeout: 900s  # 15분

# 처리량
- 100개 샤드
- 각 샤드당 10개 병렬 처리
- 최대 1000개 동시 Lambda 실행
```

#### 7.2 순서 보장 중요 시
```python
# Lambda 함수 설정
BatchSize: 100
ParallelizationFactor: 1
MemorySize: 128MB
Timeout: 60s

# 처리 특성
- 샤드당 단일 Lambda
- 순차적 처리 보장
- 처리량보다 순서가 중요한 경우
```
