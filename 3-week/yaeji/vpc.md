# AWS VPC (Virtual Private Cloud)

## VPC 개요
VPC는 Virtual Private Cloud로 AWS 클라우드에 있는 사설 네트워크를 의미합니다. AWS 리소스를 배포할 수 있는 가상 네트워크입니다. VPC는 리전 리소스로, AWS 리전이 2개일 때 2개의 다른 VPC를 갖게 됩니다.

### 주요 특징
- **VPC는 IP 범위(CIDR 범위)를 갖고 있습니다**
- **논리적인 구조인 VPC 내부에는 서브넷이 있고 이것이 VPC 안에 있는 네트워크를 분할하게 해줍니다**
- 기본 VPC는 AWS에서 계정을 생성할 때 자동으로 생성됩니다

## 서브넷

### 개념 및 특징
- **서브넷은 가용 영역(AZ) 수준에서 정의됩니다**
- 서브넷은 VPC의 네트워크 분할을 담당합니다
- **서브넷은 공용(Public) 서브넷과 사설(Private) 서브넷으로 구분됩니다**

### 공용 서브넷 vs 사설 서브넷
- **공용 서브넷**: 인터넷으로부터 접근 가능, 월드 와이드 웹(WWW)에 접근 가능
- **사설 서브넷**: 인터넷에서 직접 접근 불가능, 보안이 중요한 리소스를 위해 사용

### 라우팅 테이블
- 인터넷으로의 접근과 서브넷 사이의 접근을 정의하기 위해 사용
- VPC 내에서 여러 라우팅 테이블을 정의하여 네트워크 트래픽 흐름 방향 설정

## 게이트웨이 및 연결

### 인터넷 게이트웨이 (IGW)
- **인터넷 게이트웨이는 VPC 인스턴스가 인터넷에 연결되도록 지원합니다**
- **공용 서브넷은 인터넷 게이트웨이로 직접 라우팅됩니다**
- VPC 수준에서 정의됩니다

### NAT 게이트웨이/NAT 인스턴스
- 사설 서브넷의 EC2 인스턴스가 인터넷에 접근할 수 있게 해줍니다
- 인터넷에서 사설 서브넷으로의 접근은 차단됩니다
- **NAT 게이트웨이**: AWS에서 관리, 프로비저닝과 스케일링 자동화
- **NAT 인스턴스**: 자체 관리 필요

#### 작동 방식
1. NAT 게이트웨이/인스턴스는 공용 서브넷에 배포됩니다
2. 사설 서브넷에서 NAT 게이트웨이/인스턴스로 트래픽이 라우팅됩니다
3. NAT 게이트웨이/인스턴스는 인터넷 게이트웨이로 트래픽을 전달합니다
4. **사설 서브넷이 NAT을 통해 인터넷으로 접근할 수 있습니다**

## 보안

### NACL (Network Access Control List)
- **NACL은 서브넷을 오고 가는 트래픽을 제어하는 방화벽입니다**
- **허용 규칙과 거부 규칙을 모두 가질 수 있습니다**
- **서브넷에 연결되며 규칙은 IP 주소만을 기반으로 합니다**
- 무상태(Stateless) 방식: 인바운드와 아웃바운드 트래픽을 각각 별도로 평가
- **인터넷에서 오고 가는 트래픽은 먼저 NACL을 통과해야 합니다**
- 기본 NACL은 모든 트래픽의 출입을 허용합니다

### 보안 그룹 (Security Group)
- EC2 인스턴스나 ENI(탄력적 네트워크 인터페이스)의 트래픽 제어
- **허용 규칙만 있고 거부 규칙은 없습니다**
- **IP 주소 또는 다른 보안 그룹을 참조할 수 있습니다**
- 상태 유지(Stateful) 방식: 허용된 인바운드 트래픽의 응답은 자동 허용

### NACL vs 보안 그룹 비교

| 특성 | NACL | 보안 그룹 |
|------|------|----------|
| 적용 대상 | 서브넷 | 인스턴스/ENI |
| 규칙 | 허용 및 거부 | 허용만 가능 |
| 상태 | 무상태(Stateless) | 상태 유지(Stateful) |
| 평가 | 규칙 번호 순서대로 | 모든 규칙 평가 |
| 범위 | 모든 트래픽 | 지정된 트래픽만 |

## VPC Flow Logs

- **VPC Flow Logs는 VPC 내 인터페이스로 가는 모든 IP 트래픽 정보를 수집합니다**
- 다음 수준에서 Flow Logs를 생성할 수 있습니다.
  - VPC 수준
  - 서브넷 수준
  - ENI(탄력적 네트워크 인터페이스) 수준
- 모니터링 및 연결성 문제 해결에 도움이 됩니다
- 허용 및 거부된 모든 트래픽에 대한 정보 제공
- **Elastic Load Balancer, ElastiCache, RDS, Aurora 등 AWS 관리 서비스도 VPC Flow Logs에 표시됩니다**
- 로그 데이터는 Amazon S3, CloudWatch Logs, Kinesis Data Firehose로 전송 가능

## VPC 연결 옵션

### VPC 피어링
- 서로 다른 VPC를 마치 같은 네트워크에 있는 것처럼 연결
- AWS의 네트워크를 이용해 프라이빗하게 통신
- 요구사항:
  - 각 VPC의 IP 범위(CIDR)가 겹치지 않아야 함
  - **VPC 피어링 연결은 전이적이지 않음** (A-B, B-C 연결이 있더라도 A-C는 직접 연결 필요)

### VPC 엔드포인트
- AWS 서비스에 연결할 때 프라이빗 네트워크 이용 가능
- 공개 인터넷을 통하지 않고 AWS 서비스에 접근
- 보안 강화 및 지연 시간 감소
- 유형:
  - **게이트웨이 엔드포인트**: S3, DynamoDB 전용
  - **인터페이스 엔드포인트**: 기타 AWS 서비스용 (CloudWatch 등)

### 온프레미스 연결 옵션

#### Site-to-Site VPN
- 온프레미스 VPN 어플라이언스를 AWS와 연결
- 연결은 자동으로 암호화됨
- 공개 인터넷을 통해 연결
- 구축이 빠르고 쉬움 (몇 분 소요)

#### Direct Connect
- 온프레미스 데이터센터와 AWS를 물리적으로 연결
- 프라이빗 네트워크 연결 (공개 인터넷 사용 안 함)
- 안전하고 빠른 연결
- 구축에 몇 개월이 소요될 수 있음

## 3계층 아키텍처

전형적인 3계층 솔루션 아키텍처는 다음과 같이 구성됩니다.

### 웹 계층 (프레젠테이션 계층)
- 공용 서브넷에 위치
- 사용자 요청을 처리하는 Elastic Load Balancer(ELB) 포함
- Route 53을 통한 DNS 쿼리 처리
- 여러 가용 영역에 걸쳐 분산 배치

### 애플리케이션 계층 (비즈니스 로직 계층)
- **사설 서브넷에 위치**
- EC2 인스턴스로 구성된 Auto Scaling Group
- **인터넷에서 직접 접근할 필요 없이 ELB를 통해서만 접근 가능**
- 여러 가용 영역에 걸쳐 분산 배치

### 데이터 계층
- 데이터 서브넷에 위치 (사설 서브넷의 다른 형태)
- Amazon RDS와 같은 데이터베이스 서비스
- ElastiCache를 통한 캐싱 기능
- 애플리케이션 계층에서만 접근 가능

### LAMP 스택
AWS에서 자주 볼 수 있는 LAMP 스택 구성:
- **L**: Linux (EC2의 운영체제)
- **A**: Apache (웹 서버)
- **M**: MySQL (RDS의 데이터베이스)
- **P**: PHP (애플리케이션 로직)

### 추가 구성 요소
- Redis/Memcached (ElastiCache)를 통한 캐싱
- EBS 드라이브를 EC2 인스턴스에 연결하여 로컬 데이터 저장
- EFS를 사용하여 여러 EC2 인스턴스 간 파일 공유 (예: WordPress 이미지)

## 요약

- **VPC**: AWS 클라우드 내의 가상 사설 네트워크, 리전 단위 리소스
- **서브넷**: VPC 내 네트워크 분할, 가용 영역 단위 리소스
- **인터넷 게이트웨이**: 공용 서브넷과 인터넷 연결
- **NAT 게이트웨이/인스턴스**: 사설 서브넷의 인터넷 접근 지원
- **NACL**: 서브넷 수준의 무상태 방화벽
- **보안 그룹**: 인스턴스 수준의 상태 유지 방화벽
- **VPC 피어링**: 서로 다른 VPC 간 연결
- **VPC 엔드포인트**: AWS 서비스에 대한 프라이빗 연결
- **VPC Flow Logs**: 네트워크 트래픽 로깅 및 모니터링
- **Site-to-Site VPN**: 공개 인터넷을 통한 온프레미스 연결
- **Direct Connect**: 프라이빗 네트워크를 통한 온프레미스 연결
