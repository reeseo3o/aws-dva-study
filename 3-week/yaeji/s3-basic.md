# Amazon S3 기본 개념

## 개요
Amazon S3(Simple Storage Service)는 AWS의 핵심 서비스 중 하나로, **무한대로 확장이 가능한** 객체 스토리지 서비스입니다. 많은 웹 사이트들과 AWS 서비스들이 S3를 백본으로 사용하고 있어 AWS 생태계에서 매우 중요한 위치를 차지하고 있습니다.

### 주요 특징
- **확장성**: 무한대로 확장 가능
- **내구성**: 99.999999999%(11개의 9)의 높은 내구성
- **가용성**: 스토리지 클래스에 따라 99.5%~99.99%의 가용성 제공
- **보안성**: 다양한 보안 기능 제공
- **성능**: 짧은 지연 시간과 높은 처리량

## 주요 사용 사례
- **백업 및 스토리지**: 파일 저장, 디스크 백업
- **재해 복구**: 리전 간 데이터 이관
- **기록 보관**: 장기 데이터 보관
- **하이브리드 클라우드 스토리지**: 온프레미스와 클라우드 환경 연계
- **데이터 레이크**: 대량의 데이터 저장 및 빅데이터 분석
- **소프트웨어 배포**: 업데이트 파일 배포
- **정적 웹사이트 호스팅**: HTML, CSS, JavaScript 파일 호스팅

### 실제 사례
- **나스닥**: 7년치 데이터를 S3 Glacier 서비스에 아카이빙
- **시스코**: S3를 활용한 데이터 분석 및 비즈니스 인사이트 도출

## S3 버킷과 객체

### 버킷(Bucket)
- 최상위 디렉터리 개념
- **AWS 전체에서 전역적으로 고유한 이름** 필요
- 버킷은 **리전 단위로 정의**됨 (S3는 글로벌 서비스처럼 보이지만 실제로는 리전 서비스)

#### 버킷 이름 규칙
- **대문자와 언더바(_) 사용 불가**
- 길이: 3~63자
- IP 주소 형식 불가
- 소문자나 숫자로 시작
- 소문자, 숫자, 하이픈(-)만 사용 가능

### 객체(Object)
- 버킷에 저장되는 파일
- 각 객체는 고유한 키(Key)를 가짐
- 키는 파일의 전체 경로 (예: `my_folder/another_folder/my_file.txt`)
- 키는 접두사(prefix)와 객체 이름으로 구성

#### 객체 특성
- **최대 크기: 5TB**
- **5GB 이상 파일은 멀티파트 업로드 필요**
- **메타데이터**: 키-값 형태로 객체 속성 정의
- 태그: 최대 10개까지 지정 가능
- 버전 ID: 버전 관리 활성화 시 부여됨

## S3 보안

### 사용자 기반 보안
- **IAM 정책**: 사용자별로 S3 API 호출 권한 정의

### 자원 기반 보안
- **버킷 정책**: S3 콘솔에서 직접 버킷에 권한 설정
  - 특정 사용자/계정에 접근 권한 부여
  - 계정 간 액세스 위임
  - 퍼블릭 접근 설정
- **ACL(객체 액세스 제한 목록)**: 세밀한 보안 체계 (비활성화 가능)
- **버킷 ACL**: 버킷 단위 접근 제어 (비활성화 가능)

> **Amazon S3에 가장 많이 적용하는 보안은 버킷 정책입니다.**

### 버킷 정책 예시
```json
{
  "Effect": "Allow",
  "Principal": "*",
  "Action": "s3:GetObject",
  "Resource": "arn:aws:s3:::examplebucket/*"
}
```

주요 구성 요소:
1. **Resource**: 정책이 적용되는 버킷과 객체 정의
2. **Effect**: Allow(허용) 또는 Deny(거부)
3. **Action**: 허용/거부할 API 액션
4. **Principal**: 정책을 적용할 사용자/계정

### 퍼블릭 액세스 차단 설정
- AWS의 데이터 유출 방지를 위한 추가 보호 장치
- **이 설정이 활성화되어 있으면** 버킷 정책으로 퍼블릭 액세스를 허용해도 적용되지 않음
- 계정 수준 또는 버킷 수준에서 설정 가능

### 보안 사례
1. **퍼블릭 웹사이트 액세스**: 버킷 정책으로 퍼블릭 읽기 권한 부여
2. **같은 계정 내 IAM 사용자 접근**: IAM 권한으로 접근 제어
3. **EC2에서 S3 접근**: **IAM 역할 사용**
4. **계정 간 액세스**: 버킷 정책으로 다른 계정의 IAM 사용자에게 권한 부여

## 정적 웹사이트 호스팅
- S3 버킷을 이용한 정적 웹사이트 호스팅 가능
- 웹사이트 URL 형식:
  - `http://bucket-name.s3-website-region.amazonaws.com`
  - `http://bucket-name.s3-website.region.amazonaws.com`
  - **차이점: 하이픈(-) vs 마침표(.)**
- 필요 조건: 버킷에 퍼블릭 읽기 권한 설정 (버킷 정책)

> **S3 버킷에 읽기 권한을 줬는데도 403 Forbidden 에러가 발생하면** 퍼블릭 액세스 차단 설정을 확인하세요.

## 버전 관리
- 버킷 단위로 설정 가능
- **같은 키로 파일을 다시 업로드하면 새 버전 생성** (덮어쓰기 대신)

### 이점
- **의도하지 않은 삭제 방지**: 삭제 시 삭제 마커만 추가됨
- **이전 버전으로 롤백 용이**

### 주의사항
- 버전 관리 활성화 전 기존 파일들의 버전은 null
- 버전 관리 일시 중지 시 이전 버전은 유지됨

## S3 복제
- **CRR(Cross-Region Replication)**: 교차 리전 복제
- **SRR(Same-Region Replication)**: 동일 리전 복제

### 요구사항
- 소스와 대상 버킷 모두 버전 관리 활성화 필요
- 서로 다른 AWS 계정에 속한 버킷 간 복제 가능
- S3 서비스에 적절한 IAM 권한 부여 필요

### 작동 방식
- 비동기식 복제 (백그라운드에서 진행)
- 복제에 필요한 IAM 권한 설정 필요

### 사용 사례
- **CRR**: 컴플라이언스, 저지연 액세스, 계정 간 데이터 복제
- **SRR**: 로그 집계, 운영/테스트 환경 간 라이브 복제

## S3 스토리지 클래스

### S3 Standard
- 기본 스토리지 클래스
- 자주 액세스하는 데이터 저장
- 가용성: 99.99%
- 지연 시간 짧고 처리량 높음
- 2개의 시설 동시 장애 견딤
- 적합 사용처: 빅데이터 분석, 모바일 앱, 게임, 콘텐츠 배포

### S3 Infrequent Access(IA)
- **덜 자주 사용하는 데이터용**
- S3 Standard보다 저렴하지만 데이터 조회 시 비용 발생
- 가용성: 99.9%
- 적합 사용처: **재해 복구, 백업**

### S3 One Zone-IA
- 단일 가용 영역에만 데이터 저장
- 가용 영역 장애 시 데이터 손실 가능
- 가용성: 99.5%
- 적합 사용처: 온프레미스 데이터 백업, 재생성 가능 데이터

### Glacier 스토리지 클래스
저렴한 객체 스토리지로 아카이브/백업용

#### Glacier Instant Retrieval
- **밀리초 단위 검색**
- 분기당 한 번 접근하는 데이터에 적합
- 최소 스토리지 기간: 90일
- 적합 사용처: 빠른 액세스가 필요한 백업

#### Glacier Flexible Retrieval (구 Amazon S3 Glacier)
- 검색 옵션:
  - Expedited: 1~5분
  - Standard: 3~5시간
  - Bulk: 5~12시간 (무료)
- 최소 스토리지 기간: 90일

#### Glacier Deep Archive
- **장기 보관용**
- 검색 옵션:
  - Standard: 12시간
  - Bulk: 48시간
- 최소 스토리지 기간: 180일
- 가장 저렴한 스토리지 클래스

### S3 Intelligent-Tiering
- **액세스 패턴에 따라 객체를 자동으로 티어 간 이동**
- 월별 객체 모니터링 및 자동 이동 비용 발생 (별도 검색 비용 없음)
- 티어 구성:
  - 빈번한 액세스 티어 (기본)
  - 빈번하지 않은 액세스 티어 (30일 미접근)
  - Archive Instant Access (90일 미접근)
  - Archive Access (90~700일 미접근, 선택사항)
  - Deep Archive Access (180~700일 미접근, 선택사항)

### 스토리지 클래스 비교

| 스토리지 클래스 | 내구성 | 가용성 | 가용 영역 | 최소 스토리지 기간 | 검색 시간 |
|----------------|-------|-------|----------|-----------------|----------|
| S3 Standard | 99.999999999% | 99.99% | ≥ 3 | 없음 | 밀리초 |
| S3 IA | 99.999999999% | 99.9% | ≥ 3 | 30일 | 밀리초 |
| S3 One Zone-IA | 99.999999999% | 99.5% | 1 | 30일 | 밀리초 |
| Glacier Instant Retrieval | 99.999999999% | 99.9% | ≥ 3 | 90일 | 밀리초 |
| Glacier Flexible Retrieval | 99.999999999% | 99.9% | ≥ 3 | 90일 | 분~시간 |
| Glacier Deep Archive | 99.999999999% | 99.9% | ≥ 3 | 180일 | 시간~일 |
| S3 Intelligent-Tiering | 99.999999999% | 99.9% | ≥ 3 | 없음 | 티어에 따라 다름 |
