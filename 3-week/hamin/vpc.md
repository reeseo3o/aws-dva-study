# VPC

VPC는 AWS 클라우드 내에서 논리적으로 분리된 가상 네트워크를 말합니다. 온프레미스(사내) 환경에서 사용하는 LAN과 유사한 개념입니다.

CIDR 블록: VPC를 구성할 때 IP 주소 범위를 지정해야 하며, 예시로 10.0.0.0/16 등이 있습니다. 이는 10.0.0.0부터 10.0.255.255까지 할당할 수 있는 IP 주소 범위를 뜻합니다.

VPC 구성 요소: 각 VPC 안에는 여러 개의 서브넷, 라우팅 테이블, 보안 그룹, NACL, NAT Gateway, IGW 등이 존재할 수 있습니다.

### 서브넷 (Subnet)

서브넷은 VPC 내에서 IP 주소 블록(CIDR)을 더 세분화한 네트워크 구역입니다. 각 서브넷은 특정 가용 영역에 속하며, 퍼블릭 또는 프라이빗으로 나뉘게 됩니다.

- 퍼블릭 서브넷: 인터넷 게이트웨이(IGW)를 통해 외부 인터넷과 통신할 수 있는 서브넷
- 프라이빗 서브넷: 직접 인터넷과 통신하지 않으며, 주로 내부 애플리케이션 서버나 데이터베이스 서버용으로 사용

### 라우팅 테이블 (Route table)

라우팅 테이블은 서브넷 트래픽이 어디로 전달되어야 하는지 결정합니다.

기본 라우팅 테이블(Main Route Table)과 사용자 정의 라우팅 테이블이 있으며, 서브넷은 하나의 라우팅 테이블과 연결됩니다.

퍼블릭 서브넷의 경우: 0.0.0.0/0 → IGW 경로를 추가

프라이빗 서브넷의 경우: 0.0.0.0/0 → NAT Gateway 경로를 추가(아웃바운드만 필요할 때)


### IGW (Internet Gateway)

인터넷 게이트웨이(IGW)는 VPC의 리소스가 공인 인터넷과 통신할 수 있도록 해주는 논리적 장치입니다.
IGW는 VPC 당 하나만 할당할 수 있으며, 고가용성이 기본적으로 보장되는 AWS 관리형 서비스입니다.

- 퍼블릭 서브넷이 IGW와 연결되어 있어야 외부와 통신이 가능합니다.
- IGW를 사용하려면 해당 서브넷의 라우팅 테이블에 IGW를 향한 경로가 설정되어 있어야 합니다.

### NAT Gateway / NAT 인스턴스

프라이빗 서브넷에 있는 리소스는 직접 인터넷에 연결할 수 없습니다. 하지만 외부 API 요청 등을 위해 아웃바운드 인터넷 연결이 필요할 수 있습니다. 이때 NAT(Network Address Translation)를 사용합니다.

- NAT Gateway: AWS에서 제공하는 관리형 서비스. 고가용성, 고성능.
- NAT 인스턴스: EC2 인스턴스를 직접 NAT 서버로 구성. 설정 복잡, 관리 부담 큼.

프라이빗 서브넷에서 NAT를 통해 인터넷에 접근할 수 있지만, 외부에서 이 리소스에 직접 접근하는 것은 불가능합니다.

## NACL, 보안 그룹, VPC Flow Logs

### NACL (Network Access Control List)

NACL은 서브넷 단위에서 트래픽을 제어하는 네트워크 수준의 방화벽입니다.

Stateless: 요청 트래픽과 응답 트래픽을 별도로 확인합니다. 인바운드와 아웃바운드를 각각 허용(Allow)해야 연결이 됩니다.

규칙 순서: NACL 규칙에는 번호가 있으며, 작은 번호부터 평가를 시작합니다. 가장 먼저 일치하는 규칙을 적용한 뒤 평가를 중단합니다.

허용(Allow), 거부(Deny) 규칙을 모두 명시적으로 설정할 수 있습니다.

한 서브넷에는 하나의 NACL만 적용됩니다. 기본적으로는 기본 NACL이 할당되며, 이는 모든 트래픽을 허용하는 설정을 가집니다.

사용 예시)
특정 IP나 포트에서 들어오는 트래픽을 서브넷 수준에서 차단하기
서브넷 단위의 보안 규칙을 중앙에서 쉽게 관리하려는 경우
인바운드와 아웃바운드를 아주 세밀하게 제어해야 하거나, 공인 IP를 갖는 공격 트래픽을 서브넷 수준에서 차단할 때



### 보안 그룹 (Security Group)

보안 그룹은 각 EC2 인스턴스나 AWS 리소스(RDS, Elastic Load Balancer 등) 수준에서 적용되는 가상 방화벽 역할을 합니다.

Stateful: 인바운드 규칙에서 허용된 트래픽은, 그 트래픽에 대한 응답은 자동으로 허용됩니다.
(반대로 아웃바운드 규칙에서도 동일하게 작동)

명시적인 허용(Allow) 규칙만 설정할 수 있으며, 명시적 거부 규칙은 없습니다. 허용되지 않은 모든 트래픽은 암묵적으로 거부됩니다.

인스턴스나 리소스에 하나 이상의 보안 그룹을 할당할 수 있으며, 여러 보안 그룹을 중첩해서 사용할 수도 있습니다.

보통 서버(EC2)에 부착된 보안 그룹에서는 SSH(22번 포트), HTTP(80번 포트), HTTPS(443번 포트) 등을 제한적으로 열어두며, 내부 통신 등 필요한 포트만 허용합니다.


| 구분                | NACL                                         | 보안 그룹                                           |
|---------------------|----------------------------------------------|-----------------------------------------------------|
| **적용 범위**       | 서브넷 단위                                  | 인스턴스/리소스 단위                                |
| **상태(State)**     | Stateless (요청/응답 개별 판단)              | Stateful (요청 허용 시 응답 자동 허용)              |
| **규칙 설정**       | Allow, Deny 모두 명시 가능                   | Allow만 가능, Deny는 암묵적 거부                    |
| **규칙 평가 순서**  | 규칙 번호(Order)에 따라 순차적으로 평가       | 모든 규칙이 동시에 평가되며, 허용되는 트래픽은 통과 |
| **사용 목적**       | 서브넷 레벨에서 트래픽 차단/허용을 세밀하게 제어 | 개별 리소스(EC2, RDS 등) 접근 제어                  |


### VPC Flow Logs

VPC Flow Logs는 VPC, 서브넷 또는 네트워크 인터페이스에서 발생하는 IP 트래픽 정보를 캡처하여 로그로 저장하는 기능입니다.

- CloudWatch Logs 또는 S3에 저장 가능합니다.
- 네트워크 트래픽 분석, 보안 감사, 문제 해결에 활용됩니다.
- 로그에는 소스 IP, 대상 IP, 포트, 프로토콜, 허용 여부 등이 포함됩니다.

## VPC 피어링, 엔드포인트, VPN, Direct Connect

### VPC 피어링 (VPC Peering)

VPC 피어링은 서로 다른 VPC 간에 프라이빗 IP 주소를 사용하여 트래픽을 주고받을 수 있도록 하는 기능입니다.

- 동일한 계정 또는 다른 계정 간에도 설정 가능
- 상호 라우팅 테이블 설정 필요
- 전이(transitive) 라우팅은 지원하지 않음

### VPC 엔드포인트 (VPC Endpoint)

VPC 엔드포인트는 VPC 내부에서 AWS 서비스(S3, DynamoDB 등)에 인터넷 없이 안전하게 접근할 수 있도록 해주는 기능입니다.

- Gateway Endpoint: S3, DynamoDB 전용
- Interface Endpoint: ENI(Elastic Network Interface)를 통해 다양한 AWS 서비스와 연결

엔드포인트를 사용하면 퍼블릭 IP나 NAT 없이 AWS 서비스와 안전하게 통신할 수 있습니다.

### VPN 연결

VPN은 온프레미스 네트워크와 AWS VPC 간의 안전한 암호화 통신을 가능하게 합니다.

- 인터넷을 통해 연결되며, 비용이 비교적 저렴
- 빠른 설정 가능, 보안성 우수
- Site-to-Site VPN 방식으로 구성

### Direct Connect (DX)

Direct Connect는 온프레미스 네트워크와 AWS 간의 전용 물리 회선을 통해 연결하는 방식입니다.

- 고대역폭, 낮은 지연시간, 안정적인 품질
- VPN보다 비용은 더 비싸지만, 장기적인 대규모 통신에 적합
- 하이브리드 클라우드 환경에서 자주 사용됨
